# 莉拉OK! / Liraoke

Windows 卡拉 OK 风视频制作工具，英文名 Liraoke 呼应 karaoke。当前内部版本 **0.4.4.3**：歌词仅提前 6 秒预显，前奏／长间奏不再一直挂词；前方至少 6 秒空档的句子自动显示三根递减竖线进句提示，无需额外打点。预览和导出同步，保留五种音频可视化、歌词映射精修、注音扫色、工作区裁切、节拍器吸附、图片背景与横竖画幅等既有功能。

版本号采用 `major.minor.build.hotfix` 四段格式。`0.4.x.x` 用于内部收尾与体验简化；首个对外开放版本计划为 `0.5.0.0`，不代表本次已经完成公开发布验收。

## 运行 MVP

打开 `artifacts/package/Liraoke-0.4.4.3-win-x64/Liraoke.exe`。也可将 `artifacts/package/Liraoke-0.4.4.3-win-x64.zip` 完整解压到其他 Windows x64 电脑后运行。旧版包保留。本次项目格式仍为 schema 8，与 0.4.4.0 相同；旧项目默认 A 经典左下频谱，保留开关、裁切、节拍器、歌词和打轴。保存后请继续用支持 schema 8 的版本编辑，更早旧版会拒绝新格式以免丢失所选样式。

新项目在工作区根目录生成 `<项目名>.lrn`，它直接保存项目配置并引用工作区内的相对素材路径。通过“打开工作区”选择文件，或运行 `Liraoke.exe "D:\歌曲工作区\歌曲.lrn"` 打开；在 Windows 中为 `.lrn` 选择 Liraoke.exe 并设为默认应用后可双击打开。便携包不会自行修改系统文件关联。仍可打开原 `project.kfp` 单轨项目；按当前未公开发布的范围，不提供旧多轨项目转换，含额外视频轨内容的项目会明确拒绝，不会静默丢片段。

`%LOCALAPPDATA%/KaraokeFilmMaker/` 中的目录记忆不变。内部解决方案和命名空间暂时保留 KaraokeFilmMaker，避免无关迁移。图标原图保存在 `src/KaraokeFilmMaker.App/Assets/Liraoke.source.png`；`scripts/build-app-icon.ps1` 只进行尺寸缩放与 ICO 封装，生成 16/24/32/48/64/128/256 像素图层，不重绘图案。

便携包包含 .NET 运行时、固定版本 FFmpeg 和日文词典，不需要安装 Visual Studio、SDK、全局 FFmpeg 或日语语音包。不要只复制 EXE。

1. 创建新的空工作区，导入歌曲和背景视频／图片；素材会复制进工作区。
2. 在“歌词获取 / 预览”导入 TXT/LRC/SRT，或使用“联网搜索歌词”（含粘贴入口）；默认离线自动识别语言并准备读音，也可指定主要语言提示。该选择只作用于新挂载内容，不会在保存时改写已有歌词。双击某行可直接修改原文，右键可复制整行或在该行前／后插入。
3. 切换到“歌词打轴”，选择起始句，中文按字、英文按单词、日语按演唱音节。P 播放/暂停，每个单元开始时按一次空格；自动跨句。完整句结束时 Enter 记录尾字结束并应用，再继续下一句；退格回退一个单元，Esc 暂停。无需预先记录行时间。
4. 编辑歌词、单元映射和时间，移动／拼接视频或图片、调整片段时长；按需开启频谱，选择字幕预设和本机字体。
5. 选择画幅比例、1080p/720p 和 24/30/60 fps，按需裁切成片范围，保存项目并导出 MP4。

### 工作区裁切（0.4.3.3）

在预览页下方“工作区裁切”输入起点／终点秒数，或暂停后把时间轴播放头移动到目标位置，点击“当前位置设为起点／终点”，再点击“应用裁切”。时间轴蓝线标出边界，灰色区域不导出，“成片”显示实际输出长度。比如歌曲长 200 秒、最后 5 秒无声，起点保留 0、终点设为 195 即可。它是手动范围选择，不自动检测静音。

- 范围限定在主歌曲时长内，默认整首；比歌曲更长的视频尾部仍不进入成片。
- 只改变预览播放与导出范围，不删除文件、不裁断／挪动歌词打点或视频片段。导出文件从 0 开始，音频、视频原声混音、图片、字幕高亮和频谱同步读取原时间轴的对应位置。
- 预览播放从范围内开始，到终点暂停，再次播放从裁切起点开始。“回到起点”及 Home／End 使用裁切边界。暂停时仍可在完整时间轴浏览，以重新选取或扩大范围；打轴页始终使用完整歌曲，不受裁切限制。
- 点击“恢复全长”取消裁切；应用／恢复支持项目撤销重做，裁切设置随 `.lrn` 和自动恢复文件保存。输入框是草稿，需点击“应用裁切”才生效。
- 更换或移除主歌曲时自动恢复全长，避免沿用上一首歌曲的范围；导入／编辑背景视频或图片不改变裁切范围。

工作区采用相对路径，可整体移动；每 20 秒检查并保存独立恢复文件，打轴播放期间延后检查，避免序列化和写入打断输入。打开时提示恢复，不覆盖最后一次显式保存。

关闭有未保存更改的工作区时，弹窗明确提供“保存 / 不保存 / 取消”：保存成功后关闭，快速编辑框内未应用的文字/读音草稿也会一并提交；不保存则不更新项目文件（已应用编辑仍保留独立恢复点，快速编辑草稿放弃）；取消、Esc 或关闭弹窗均返回编辑。项目无改动不重复提示，自动恢复点不等于明确保存。未应用/可重做的录制打点会单独警告，需先返回按 Enter 应用，或明确确认放弃；保存失败默认返回编辑，可另行确认继续关闭。

新建工作区、打开工作区、导入歌曲、导入视频、导入歌词、加载语言插件和导出视频各自记住上次确认选择的目录，取消不更新。首次打开工作区时优先定位到已创建的工作区；首次导出默认使用当前工作区的 `exports/`，此后优先使用导出按钮自己的记录。记忆目录消失时退回仍存在的上级目录。设置保存在当前 Windows 用户的 `%LOCALAPPDATA%/KaraokeFilmMaker/dialog-locations.json`，重启或升级便携包仍有效，不写入项目文件。

## 自动语言识别与语言插件

- 导入后用文字特征、插件词典／规则和整句／歌曲上下文识别，不调用 AI、不联网。汉字不直接等于中文，拉丁字母不直接等于英文；歧义、未知语言和未完成日语读音会提示待确认。
- 0.4.2.1：语言识别不确定（包括暂未确定语言）但已有完整可打分词时，不阻止开始或继续打轴；仅在实际录制到该句时显示非模态提醒，不暂停播放、不拦截空格、不抢键盘焦点。“忽略本句提示”在本次运行中隐藏该句提醒，不视为人工确认或修改数据。用户可自行检查、在“语言 / 片段…”确认或修正，无需改动正确的分词。缺少必要日语读音、无效单元／显示映射、插件分析／校验错误仍阻止录制。已有项目无需重新导入，不重建单元、ID、显示快照或已打时间。
- 打轴页“语言 / 片段…”可选中原文、指定语言并锁定，或重新自动识别选区。日语可填写片段假名；其他插件须声明支持片段手工读音，否则使用单元精修。片段改动涉及已打轴单元时先询问，选区外单元、ID 和时间保留，操作可撤销。
- 内置中文、英语、日语使用同一套 `BaseLanguageAdaptor` / `BaseLanguagePolicy`。语言包负责识别线索、读音、演唱单元、打轴格子、字幕注音／转写和录制校验；播放器、时间轴及绘制仍由宿主管理。
- 歌词获取页“语言插件…”可显式加载可信 DLL，需先确认第三方代码权限。本次运行有效，下次运行需重新加载；不会自动扫描、下载或执行项目中的 DLL。加载插件不会自动重分析旧歌词。
- 项目保存语言片段、人工锁定、插件版本和显示快照。缺少插件仍能使用已有结果打轴、预览、导出和保存；会重建语言显示的文字／读音编辑需先加载插件。旧 schema 1／2 不重新生成已打轴单元。
- 当前插件显示协议支持 LTR；RTL／复杂双向排版尚未开放。第三方语言准确性需作者及熟悉该语言的人验证，不能因插件成功加载就视为完整语言支持。

接口、构建与示例见 [语言包开发说明](docs/LANGUAGE_PLUGINS.md)。仓库西语示例只演示 API，不是完整的西语语言包。

## 卡拉 OK 逐字录制

“歌词获取 / 预览”支持双击行内修改原文，文本框可选择、复制和粘贴，Enter／“应用修改”提交，Esc／“取消”放弃草稿。修改原文重建本句语言／读音／单元，本句起止时间和其他句打轴保持不变；已有逐字打点时先确认清除本句打点。未应用草稿会阻止切换到其他页、另一个编辑行或执行会覆盖内容的操作；保存时可一并应用，关闭时纳入“保存／不保存／取消”询问。

右键某行选择“在此行之前／之后插入歌词”，也可用“新增歌词行”从空列表开始。新行默认未打轴；前后两句有实际时间且首尾相接或重叠时，弹窗明确提示清除新句及其后所有歌词的行时间、逐单元时间、原始敲击与打点确认，前一句及其结束时间不变。取消不插入、不改时间；确认后保留后续原文、读音、语言片段与显示映射，打轴页浏览句定位到新句。真实时间空隙、列表首尾和纯未打轴歌词插入不清除已有时间。编辑和插入均可项目撤销／重做。

日语打轴单元和字幕注音是两种显示规则。例如「駅まで走ってった」仍按演唱单元打点（保留「は｜しっ」），字幕则只在「走」上方标「はし」，字面的「っ」不进入汉字注音。字幕以原文中的假名作为对齐边界，唯一对应时拆出汉字读音；不会直接删除所有促音/拨音，「一緒＝いっしょ」「本＝ほん」保持完整。无法唯一对齐的手工映射仍保留原词组，不猜测新读音。罗马音模式仍作演唱单元的发音参考。此调整仅影响预览/导出的假名排版，打轴格、快捷编辑范围、单元 ID、时间与原始敲击记录不变；旧项目打开即可生效。

在歌词格区域滚动鼠标滚轮可逐句向前/向后浏览整首歌词，也可使用 ↑ / ↓ 按钮；每次只呈现浏览句和下一句，间奏等非演唱行也能访问。滚轮不跳音频、不改起始句或待打单元，定时刷新也不抢回视图；“回到打点位置”恢复跟随，再次按空格也会回到真正的待打位置。横向长句仍使用横向滚动条。

“从浏览句开始打轴”用于明确改变起始句，不会移动音频。若有未应用或可重做打点，先应用或清空才能切换。“编辑整句”可修改文字、假名/拼音、罗马音、翻译、行时间、读音确认和间奏/扫色等属性；“单元精修”编辑细粒度映射；“更多编辑”可新增/删除、调整句序和重新分组。原文也可在获取页双击修改；细粒度读音、分组和时间仍在打轴页精修。整句/增删/分组可能改变单元，因此需要先处理本次待应用打点；逐单元快捷修正、边界换行和合并仍可保留待应用打点。

打点使用内存列表、撤销栈和歌词模型维护；LINQ 用于查询/转换，不是存储容器。敲击不生成字幕视频或写入项目文件。完整句结束按 Enter 将本次打点应用到内存项目，再保存项目；未应用打点不在项目/恢复文件内，导出前会阻止遗漏，关闭前会提醒。预览页仍可检查动画，只有最终导出才编码成品。

0.4.3.4 起，顶部原“重做”和打轴页原“重做打点”统一为“重新打轴”。点击先确认，默认不执行；取消不修改项目或打点。确认后清空整首歌词的行／单元起止时间、原始敲击时间、完成标记和待应用／可重做打点，暂停并回到歌曲开头、定位首个待打单元。歌词文字、读音、罗马音、翻译、语言标记、分组、ID 与显示映射原样保留，素材、视频片段、节拍器和裁切配置不变；不重导或重新分词。有未应用的原文／快捷编辑草稿时先要求处理，避免丢失草稿。清空后的已应用时间可通过项目撤销恢复，临时打点不进入项目撤销；保存后重开仍为未打轴。Ctrl+Y 继续作为普通项目重做快捷键，不绑定清空操作。

打轴监视器不渲染字幕：主歌曲来自视频时，按歌曲时间播放该原视频；主歌曲为纯音频时显示黑屏，即使另有背景视频也不显示。当前句/下一句的静态歌词格、下一单元提示及点击选择仍保留。预览页按剪辑轨道显示视频与完整字幕，导出不受影响。

点击歌词格打开快捷编辑，输入框获得焦点时暂停播放。可以修改该单元对应的原文和读音，点击“应用修改”后按 P 继续；保留所有单元 ID、时间、原始敲击时间和待应用打点，支持项目撤销。多个音节共用汉字词组时，原文框修改共享词组，读音框只修改所选音节。快捷修改不增减音节；需要改分组时使用打轴页的“编辑整句”。共享词组内部换行仍须先调整映射。快速编辑还有未应用草稿时，翻页会提醒先应用或收起，不静默丢弃输入。

中文按字；英文按单词，`don't`、`you're`、带连字符的词保持完整，混合语言歌词中的英文也按词处理。标点和空格不单独打点。0.4.2.2 起，未映射为演唱单元的句首／句中标点在后一个词开始时直接变为已唱颜色，句尾剩余标点在最后一个演唱单元结束时变色；词内撇号／连字符仍跟随整词扫色。该规则共用于预览与导出，不新增打点、不修改原歌词或时间。

日语导入后自动准备读音，也可点“准备语言 / 读音（保留已确认打点）”；请检查汉字、专名和当字的实际唱法。缺少假名读音或仍含未识别汉字时不能开始录制，罗马音仅是可选参考，不决定分组或打点。默认分组为 `いっ｜しょ`、`せん｜じょ｜う｜が｜は｜ら`、`ちゃん`、`ディ`：促音 `っ`、拨音 `ん`、长音符 `ー` 并入前一个音，拗音/小元音组合不拆开；普通大字元音（如 `じょ｜う`）仍分开。`ヶ/ヵ` 不按小元音合并，须先按词的实际读音校正。

打轴区固定显示当前句和下一句：假名单元在上，较大的原文在下，共享汉字词组只显示一次；罗马音开启时作为单元内小字。长句不换行，随待打单元横向滚动，录完当前句自动显示下一句和下下句。可手动横向滚动并点击任一单元，用“在选中单元前换行”或“选中句与下一句合并”调整唱段；操作会暂停播放，保留单元 ID、读音映射、已有时间及本次待应用打点，支持撤销/重做。共享汉字词组内部不能直接换行，需选词组边界或先精修文字映射。

“显示罗马音”开关默认关闭，在打轴页与字幕样式页同步，并随项目保存：关闭时，日语预览/导出只在汉字词组上方标小字假名，纯假名不重复注音；开启时，以罗马音替代假名注音，分别对齐对应的汉字和假名。布局为长读音预留宽度，预览与导出共用渲染器。此日语模式优先于旧版逐行辅助行选项，中英文辅助行保持原有规则。

0.4.3.4 起，日语无注音句同样预留注音行高度，主字幕与有注音句的下行使用一致的高度缩放和基线，不会因为没有汉字注音就放大。适用于旧日语项目、自动／混合语言显示快照与罗马音模式，预览和导出一致；过长句子的横向防溢出缩小仍保留。

0.4.3.5 起，可在“单元精修”双击“对应歌词”修改该演唱单元映射到的原文字，不修改歌词原文。例：`思い出` 的四个打点仍是 `お／も／い／で`，将对应歌词分别改为 `思／思／い／出`，得到显示分组 `思（おも）・い・出（で）`。读音、微秒级时间、原始敲击时间和确认状态保持不变；不需重新打轴。文字范围与对应歌词实时同步；有多处相同文字时优先定位当前范围，否则提示使用从 1 开始的范围（例如 `9-9`），非法／越界／切断组合字符或跨语言片段的映射不能应用。注音（含罗马音）按下方对应字的实际扫色比例同步，不再单独按整个词的平均打点进度提前扫色；已有项目无需重新分组即可修复显示，预览和导出一致。

修改整句假名会同步重建单元，适合校正“戦場ヶ原 → せんじょうがはら”；整句手动重建无法确定词内逐字映射时保留词组范围，可在演唱单元编辑器精修文字范围。手改整句罗马音时用空格分隔每个单元，或在单元编辑器逐个改。旧项目不会自动重写已打好的时间；选中需要更新的行后点“按语言重新分组”，再录制这些行。重新分组会重建选中行单元时间，已有录制点时提示确认，可撤销。

- 一次空格只记一个字/单词/音节的入口，不是整行；提示条蓝色标出下一个单元，项目中已应用单元为绿色，本次待应用打点为金色，橙框为编辑位置。
- 重新打开项目自动恢复完成单元/句统计，并定位首个未完成单元；LRC 导入的估计时间不算完成。默认续录跳过已确认单元，保留它们的 ID、时间及原始敲击记录；新打点与已确认时间冲突时拒绝应用。整曲完成后显示完成提示，空格不会自动重录。
- 修改已有打点时，滚轮浏览到目标句，点“从浏览句重录”（或手动选择右侧句列表）；只有本次录完并应用的句子会替换原时间。点“续录未完成”返回自动进度。右侧打点列表仅列本次待应用点，清空列表不会清空项目的已应用时间。
- 支持从选中句开始连续录整曲，下一句自动接上；也可每句完成后按 Enter 记录实际结束时间并应用。
- 如果整首连续录完，可以额外按一次空格记录尾字结束，再按 Enter 应用。
- Enter 应用要求最后录制的句子已经打完整，不用均分时间冒充未记录字的时间；未录的后续句不被修改。
- 退格可跨句回退一个字；原“重做打点”按钮已改为需确认的整首“重新打轴”。录制期间锁住起始句和模式，避免时间点对应错字；清空后可重新选择。
- 逐行入口仅保留为辅助模式，不是默认，不是逐字录制的前置步骤。
- 无行时间时“三秒进入”以当前播放头为目标；循环需要已完成的句时间。

## 联网歌词搜索（0.3.0 起）

在“歌词获取 / 预览”页点击“联网搜索歌词”，输入歌名及可选歌手：

- LRCLIB：所有语言默认入口，软件内搜索、版本列表、歌词预览，支持纯文本及保留已有 LRC 行时间；可比较与当前歌曲时长的差异，但不会自动确认版本。
- 粘贴已授权歌词：输入普通文本或 LRC，可记录 HTTPS 来源链接。不会从该链接抓取网页。

导入前确认使用权限；替换当前歌词/读音/打轴需要额外确认且可以撤销。原文及来源说明保存到工作区 `lyrics/`，来源也保存在项目中，后续歌词编辑不会丢掉来源。LRC 时间仅是初始参考，不等同于逐单元精确对齐。

不需要 AI 或 DeepSeek API Key。只有主动点击搜索才发送歌名/歌手，不上传音频、视频或工作区。LRCLIB 请求可取消，有超时、300 ms 请求间隔、5 分钟内存缓存及 Retry-After 限流处理，不后台重试；结果覆盖率及网络可用性不保证。

公开发布前按 LRCLIB 客户端要求补充项目主页/开发者联系方式（适配器支持 `projectContact` 参数），并核对发布时接口条款。服务提供文本不等于获得歌曲或歌词的视频发布授权。

未来若加入含糊歌名识别、文本整理或翻译，可评估可选 DeepSeek 适配器；当前不接入模型，不让 AI 编造或补全检索不到的歌词。

接口资料：[LRCLIB API](https://lrclib.net/docs)。

## 工作区、三轨时间轴与快捷键

白底搭配极淡蓝／黄色边框，保留黑色媒体监视器；主页面为“预览”“歌词打轴”“歌词获取 / 预览”“字幕样式”。预览采用左侧项目素材、中间监视器、右侧节拍器及可折叠片段检查器、底部三轨时间轴。双击已有视频素材可再次加入唯一的视频轨道，无需重复复制文件。点击片段在检查器调整位置、入点、时长及静音；播放、分割、删除和顺序拼接放在固定工具栏。

- 预览：空格播放/暂停，左右键按导出帧率逐帧，J 回退一秒、K 暂停、L 播放，Home/End 跳转首尾；Ctrl+B 分割选中片段、Ctrl+D 复制、Delete 删除。
- 打轴：空格记录下一个字/单词/音节，P 播放/暂停，退格回退一个单元，Enter 结束完整句/录制段并应用，左右键微调 0.1 秒；其他剪辑快捷键不用于打点。
- 通用：Ctrl+S 保存，Ctrl+Z/Y 项目撤销/重做；输入框、下拉框和表格保留自身键盘操作。
- 时间轴：左右拖动视频片段移动，拖动边缘裁切；滚轮缩放、Shift+滚轮平移，Alt 拖动关闭片段吸附。

固定一条歌曲／声音轨、一条可含原声的视频轨、一条字幕轨。视频片段不允许重叠，原声随视频裁切／移动，不再单列音轨；空隙保持黑场。“顺序拼接”按片段原开始时间紧密排列，支持撤销。不再提供增轨、换轨、合轨或叠层入口。

项目素材区可“移除选中素材”；正在使用时先确认，移除其歌曲引用／视频片段，歌词与已打好的时间不变。操作可撤销，不删除工作区中的实际文件。歌词获取页的开始／结束秒只显示一位小数，按四舍五入显示，内部时间和导出精度不变。

## 前奏、间奏与自动进句提示

0.4.4.3 起，歌词预览和导出仅在每句开始前 6 秒内预显该句，结束后移除；下一句也独立遵守 6 秒窗口，双句交替槽位保持不变。开场从歌曲 0 秒算起，后续按当前句开始与此前有效歌词的最晚结束之差判断：空档 ≥6 秒时，句首自动显示三根由高到低的竖线，在开唱前 6 秒内每两秒填满一根，使用字幕未唱／已唱配色；开唱时提示消失，歌词和注音保持原位置。短空档不显示提示；无时间、空白和间奏标记行不参与歌词槽位与间隔计算。依据已保存的行起止时间，不分析音频静音，不新增或修改打点；时间、分段编辑后自动重算。暂停、跳转、变速和裁切导出均采用原歌曲时间，打轴浏览界面不受影响。

## 图片、音频可视化与字幕预设

“+ 图片”支持静态 PNG、JPG／JPEG、BMP，复制至 `media/images/` 并追加 5 秒片段；图片导入单独记忆上次目录。拖动左右边缘或修改检查器时长可延长／缩短，不受图片源时长限制；支持移动、分割、复制、顺序拼接、移除、撤销和保存重开。双击素材可重复加入视频轨，无需重新复制文件。图片无歌曲、入点或原声；与视频共用一轨，不允许重叠。图片等比例放大／缩小以铺满整个画幅，居中裁去超出部分，不拉伸；透明区域仍透出黑底。视频仍保留完整画面并按需留黑边，无片段处黑场，导出以歌曲总时长为准。

原图片保留；预览与导出共用方向规范化的 PNG 缓存，最长边不超过 1920，缓存不提前放大小图（显示／导出时按画幅放大），兼顾竖屏和方形质量。输入单边上限 16,384 像素且总像素不超过 1.2 亿，超出时提示先缩小；动画等格式需先转成静态图片。0.4.3.1 兼容被探测为 `image2` 的有效 JPEG，继续检查编码、尺寸及单帧，不把改名视频／多帧 JPEG 当作图片。素材名称左侧用不同形状的浅色矢量图标区分音频／视频／图片。缩略图加载后释放文件句柄。

预览右侧（节拍器下方，可向下滚动）“音频可视化”默认关闭，样式下拉提供：

| 样式 | 布局与配色 |
| --- | --- |
| A · 经典左下频谱 | 原 32 条蓝黄圆角柱，左下安全边距为短边 2.5%，宽度为画面 52%，最高为短边 20% |
| B · 底部密集频谱 | 128 条蓝黄柱，横向覆盖底边全宽，向上延伸，最高为短边 22% |
| C · 居中白色频谱 | 256 根白色淡透明细柱，线宽与空隙等宽（各占排列周期 50%），横向覆盖中心线全宽，上下各最高为画面高度 25%，合计 50%（横竖屏一致） |
| D · 自旋环形频谱 | 128 条白色半透明柱，内圈半径为短边 20.24%、最大柱长为短边 15.6%，满幅外径为短边 71.68%；横屏占高约 71.68%，竖屏按短边适配保持完整圆形；每 100 秒顺时针一圈 |
| E · 中低频烟花 | 白色半透明短柱向四周扩散并淡出，约 40–818 Hz 中低频能量驱动，位置分散且可复现 |

字幕绘制在可视化上层。五种样式可搭配图片／视频／黑底，开关和样式随项目保存，可撤销／重做；关闭保留选择。密集柱使用现有 32 频段插值到 128／256 柱，不声称增加采样频率分辨率，切换样式共用缓存、无需重新分析。C 白色基底不透明度约 38%，D／E 仍约 61%（烟花额外随生命周期淡出）；浅色背景上对比度较低。

按原歌曲时间采样，暂停时静止、跳转可复现、裁切后保持原时间相位，播放变速与导出一致；不改声音、歌词时间或节拍器。打轴监视器仍只显示原歌曲视频／黑屏，不播放可视化。烟花并非 AI 或重音识别：以中低频能量上升及持续能量进行稀疏触发，固定时间哈希决定位置与形态，无跨帧随机状态；单次最长 1.6 秒，同时最多 9 组、每组最多 48 根短柱，静音后已有烟花淡出，歌曲结束清空。

首次开启会准备可取消的本地缓存，之后复用；关闭时不分析／绘制。最长支持 4 小时音频，不加载整首解码 PCM；32 频段×30fps 的量化数据最多约 13.8MB（读取复制时临时内存更高），不上传、不新增模型或依赖。减少背景视频编辑可简化出片流程，但不是特定编码速度保证。

“字幕样式”提供 Liraoke、经典卡拉 OK、晴空、简约四种预设。新默认未唱为白字＋深蓝描边，已唱为当前黄色＋白描边；日语注音／罗马音和标点同步。预设修改颜色、描边、阴影，保留字体、字号、布局与注音开关，可继续精调后点击“应用字幕样式”，支持撤销／保存。颜色下拉允许手工输入合法十六进制颜色。

字体下拉枚举本机已安装字体，可输入名称搜索，包括系统提供的本地化别名；不下载字体。缺失字体时明确显示预览／导出使用的回退字体，同时保留项目原字体名。旧项目缺少已唱描边设置时保留原绘制逻辑；要采用新默认，选择 Liraoke 预设并应用。

## 项目级节拍器

预览监视器右侧设置 BPM（20–400）与首拍偏移（整数毫秒，±600000），点击“应用”；开关直接应用当前有效设置。默认关闭、120 BPM、偏移 0。正偏移表示延后第一拍，负偏移表示第一拍位于歌曲开始之前。当前仅有一组项目级设置，随项目保存并支持撤销／重做。

“吸附细分”可选整拍、二分拍、三分拍、四分拍、六分拍、八分拍，即把一拍等分为 1／2／3／4／6／8 格，默认整拍。选择后点“应用”，仅之后的新打点使用新网格；不会改变 BPM，也不会把试听节拍声加快。120 BPM 下对应格间距为 500／250／约 166.667／125／约 83.333／62.5 ms。示意图金色长线为整拍、蓝色短线为细分格，三分／六分使用绝对时间计算而不累计舍入误差。该设置随项目及恢复文件保存，自动初始化 BPM 不改细分选择。

数值框继续保留；刻度滚轮可左右拖动或滚轮调整，BPM 每格 1、Shift 微调 0.1，偏移每格 10ms、Shift 微调 1ms；聚焦后方向键也可调整。刻度下方拍点示意图随草稿更新，数值变化不会逐次重建播放音频，须点击“应用”生效。“÷2 / ×2”用于半拍／倍拍修正。较小窗口下右侧可滚动。

“自动初始化”读取项目歌曲的原始音频（歌曲来自视频亦可），使用已有 FFmpeg 和本地 C# 起音／周期相位估计，不上传素材、不调用云服务、不需要 API Key 或额外模型。最多分析开头 90 秒，自动搜索 50–240 BPM，手动设置范围仍为 20–400。相位始终相对原歌曲时间，不受视频原声混音、节拍声或播放倍速影响；返回的是一拍内第一个非负拍点位置，**不是小节第一拍／重拍识别**。

建议只填入数值草稿，须应用并试听，不自动打开节拍器，也不改已打轴时间。静音、过短、弱节奏或不够稳定的结果保留原数值；支持上方“取消任务”。显示的“稳定性”是启发式拍点一致程度，不是准确率，合成信号测试不代表真实曲库或旧电脑性能保证。半拍／倍拍和切分节奏可能产生歧义，长前奏超过分析窗口时请手动设置。

技术调研（2026-10-16）：[Beat This!](https://github.com/CPJKU/beat_this) 提供节拍／小节重拍神经网络检测，官方代码与权重采用 MIT 许可，但会引入 PyTorch 与模型运行环境；[BeatFM（2025）](https://arxiv.org/abs/2508.09790) 研究用预训练音乐模型改进节拍／重拍识别。当前热修复选择轻量固定拍点估计作为初始化辅助，未集成上述模型，也不承诺自动判断拍号或每小节重拍。

开启后，播放时节拍声与歌曲共用音频设备时钟，暂停、跳转和慢速播放均跟随歌曲。打轴先做输入延迟补偿，再吸附到歌曲范围内最近的拍点；距离相等时取后一个。歌曲范围内没有拍点，或连续输入落到同一拍点时，拒绝该点并提示，不生成零时长单元。歌曲尾部不足一拍时，可在播放终点按 Enter（或完整录制后的额外空格）使用歌曲真实终点收尾，不影响入口拍点。原始敲击时间保留，既有打轴不会被重新吸附；关闭恢复自由打轴。

节拍器是可选辅助，不是整个时间轴的依赖。0.4.3.2 起，即使有未应用／可重做打点，也能开关、修改 BPM／偏移／细分、自动初始化或撤销／重做节拍器设置；只影响之后新敲下的打点，已应用时间、临时打点与重做记录都不重新吸附。重做一个打点恢复它原来记录的时间，同一句可混合自由打点和不同节拍设置下的打点。新点仍必须晚于上一点；若新节拍吸附到上一点之前，则拒绝该新点，不移动旧点，可关闭节拍器继续自由打轴。自动初始化仍仅填入草稿。节拍声只用于试听，最终 MP4 不包含它。多 BPM／多个 timing point 与拍号配置留待后续版本。

## 已实现的功能

- `.lrn` 工作区、素材复制／移除、显式保存、自动恢复、相对路径迁移；
- 中英日歌词编辑、离线语言识别与同句多语言片段、完整语言插件接口，TXT/LRC/SRT 导入，行排序/合并/拆分，翻译及读音编辑；
- 内置 MeCab/IPADIC 日文分析，演唱音节、罗马音、显示范围映射和人工确认保护；
- 音频设备主时钟，逐行/逐单元打点、撤销/重做、局部重录、三秒进入、循环、输入延迟补偿；
- 0.5×/0.75×/1× 保音高播放、波形与图形时间轴；
- 单轨视频／图片移动/裁切/时长调整/分割/复制/删除/拼接、片段静音、歌曲与视频原声混音、空隙黑场；
- 五种可选本地音频可视化、素材类型矢量图标、四种字幕预设、本机字体搜索、独立未唱／已唱描边；
- 项目级 BPM／首拍偏移、可视化微调、离线自动初始化建议、试听节拍器、打点拍点吸附；
- 代理视频和缩略图，底部 30% 双句交替布局、逐单元扫色、字体/颜色/描边/阴影/行距/边距；
- 预览与导出共用字幕绘制器，1080p H.264/AAC MP4、24/30/60 fps、进度和取消。

自动注音不是正确读音保证：未收录专名和生僻字会保留待校对占位并标记稍后处理；请人工填写。中文拼音支持手工编辑。首版没有 AI、复杂视频特效、外部字幕工程导出或工作区压缩打包。

## 开发与打包

开发环境：.NET 10 SDK、Visual Studio 2026 的“.NET 桌面开发”工作负载。Windows x64，工程最低 API 目标为 Windows 10 1809；受支持系统和硬件目标见需求文档。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/bootstrap-media.ps1
dotnet restore KaraokeFilmMaker.slnx --configfile NuGet.Config
dotnet build KaraokeFilmMaker.slnx --no-restore
dotnet test KaraokeFilmMaker.slnx --no-build --no-restore
dotnet run --project src/KaraokeFilmMaker.App --no-restore
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/publish-mvp.ps1
```

解决方案由 App（WPF 界面）、Application（用例及编辑规则）、Domain（模型与约束）、Infrastructure（文件、媒体、音频、日文和渲染实现）以及对应四个测试项目组成。

FFmpeg 版本和下载 SHA256 固定在 `scripts/media-toolchain.json`。第三方许可证见 `THIRD_PARTY_NOTICES.txt` 及包内许可文件；本包用于内部 MVP 验收，公开分发前需完成 GPL 等对应源码及许可合规准备。
