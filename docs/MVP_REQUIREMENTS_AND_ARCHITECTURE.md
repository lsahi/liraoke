> 文档版本：0.29

> 目标平台：Windows 桌面端  
> 文档状态：MVP 功能已基本通过用户检查，进入收尾调整；未明确列入 MVP 的能力均不属于首版验收范围

## 1. 产品定义

2026-10-13 品牌决定（0.3.7）：中文名“莉拉OK!”，英文名“Liraoke”（呼应 karaoke），使用用户提供的浅蓝背景人物图片作为 Windows 图标。保留原画，封装多尺寸 ICO；启动文件和便携包采用 Liraoke 名称。原有工作区格式及本地设置目录不变，内部工程名 KaraokeFilmMaker 暂时保留。

KaraokeFilmMaker 是一款面向普通创作者的 Windows 卡拉 OK 风视频制作工具。用户将歌曲、歌词与视频素材导入独立工作区，通过内置歌词编辑器和手动打轴工作台制作按中文字、英文单词或日语演唱音节高亮的字幕，最后导出已经合成背景、歌曲和字幕的 MP4 视频。

MVP 的核心价值是：

1. 中文、日文歌词可以方便地编辑、注音和校准；
2. 即使不使用 AI，也能独立完成整首歌曲；
3. 按错可以立即撤销，任意区间可以局部重录；
4. 预览与最终导出的字幕布局和时序保持一致；
5. 项目及其素材全部包含在可移动的工作区目录内。

## 2. MVP 范围

2026-10-19 伴奏工作流优化（0.4.5.1）：伴奏不再作为素材导入或替换主歌曲，成功后写入工作区 `accompaniments/`，工程以原素材 ID、内容哈希和时长保存对应关系。schema 升至 9，旧工程空映射迁移，不猜测既有分离音频的来源。预览右侧新增“伴奏”Tab，仅提供试听开关；默认关闭，打轴始终用原歌曲，导出独立选择。导出先用复选框选择原唱和／或伴奏，再选择文件名，分别追加 ` -on vocal-`／` -off vocal-`，覆盖前确认；取消保留并提示已完成版本。主歌曲来自视频时，伴奏模式也将相同素材的移位／裁切片段路由至伴奏，不修改片段静音配置，其他视频原声不变。工具栏依次为新建／打开／制作伴奏／撤销／保存／导出／取消；“重新打轴”仅保留在打轴页播放按钮右侧。重新制作失败或取消保留旧关联，旧伴奏文件保留供撤销使用，文件丢失时禁用伴奏试听／导出并提示重新制作。此条替代 0.4.5.0 的素材导入、主歌曲替换及仅人声输出交互，安装与推理逻辑不变。

2026-10-17 六秒预显与自动进句提示（0.4.4.3）：歌词预览和导出仅在每句开始前 6 秒内预显该句，结束后移除；下一句也独立遵守 6 秒窗口，双句交替槽位保持不变。开场从歌曲 0 秒算起，后续按当前句开始与此前有效歌词的最晚结束之差判断：空档 ≥6 秒时，句首自动显示三根由高到低的竖线，在开唱前 6 秒内每两秒填满一根，使用字幕未唱／已唱配色；开唱时提示消失，歌词和注音保持原位置。短空档不显示提示；无时间、空白和间奏标记行不参与歌词槽位与间隔计算。依据已保存的行起止时间，不分析音频静音，不新增或修改打点；时间、分段编辑后自动重算。暂停、跳转、变速和裁切导出均采用原歌曲时间，打轴浏览界面不受影响。 纯渲染派生状态，不写入项目；schema 仍为 8。

2026-10-16 可视化微调（0.4.4.2，仅提升 hotfix）：C 线宽与空隙改为 1∶1，各占排列周期 50%，保留 256 柱、不透明度 96/255 和最大 50% 画面占高。D 内圈比 0.4.4.1 再增大 10%，半径为短边 20.24%，最大柱长仍为短边 15.6%，满幅外径为短边 71.68%；旋转放慢至每 100 秒顺时针一圈。竖屏按短边保留完整圆形。A／B／E 不改，schema 仍为 8，预览与导出共用参数。此条覆盖此前 C／D 的相关视觉参数。

2026-10-16 可视化微调（0.4.4.1，仅提升 hotfix）：C 从 128 柱增加到 256 柱，线宽从间距 72% 降至 32%，白色不透明度从 155/255 降至 96/255；最大上下合计占画面高度 50%，包括竖屏。D 保持 128 柱与白色透明度，内圈半径在 0.4.4.0 基础上扩大 15%，最大柱长增加 30%，满幅外径为短边 68%，横屏占高约 68%；竖屏按短边适配不裁边。旋转仍每 60 秒一圈。A、B、E 不改；音频采样、缓存和时间轴不改，预览与导出同步，schema 仍为 8。此条覆盖下面 0.4.4.0 的 C／D 初始视觉参数。

2026-10-16 音频可视化多样性（0.4.4.0）：A 保留经典左下蓝黄 32 柱；B 蓝黄 128 柱横向铺满底边；C 白色半透明 128 柱沿中心横线上下对称铺满；D 白色半透明环形 128 柱居中，原歌曲时间每 60 秒顺时针一圈；E 白色半透明短柱烟花，约 40–818 Hz 中低频能量触发，在分散位置扩散淡出。C／D／E 统一白色半透明柱形。预览右侧下拉切换，开关默认关闭、旧项目样式默认 A，保存／撤销／重做可恢复。所有样式共用原 32×30fps 缓存，密集柱为插值显示，不增加 FFT 分辨率；不新增模型、网络服务或依赖。烟花按歌曲绝对时间和固定哈希重建，最多 9 组、单组 1.6 秒、最多 48 根短柱，避免无界粒子或随机状态；跳转、变速、裁切和导出一致。静音无新效果，已有烟花淡出，歌曲结束清空；打轴页不显示可视化，不影响音频、歌词时间及节拍器。schema 升至 8 保存样式，旧项目保持开关与其他配置，旧版拒绝新格式以免丢失选择。

2026-10-16 歌词映射精修与注音扫色（0.4.3.5，仅提升 hotfix）：单元精修的“对应歌词”支持双击修改现有原文映射，与 1 起始文字范围双向同步；`思い出` 可保留四个演唱单元，映射为 `思／お、思／も、い／い、出／で`，显示为三个书写组。纯映射修改保留原文、读音元数据、ID、全部时间、原始敲击及确认状态，取消不应用；重复文字优先在原范围定位，歧义要求明确范围，非法或跨语言片段映射拒绝应用。显示快照随映射刷新。注音和罗马音的扫色由下方主字实际覆盖区间计算，不再独立使用整词单元的平均进度，因此原有整词共享映射也不会提前将“で”标黄。支持预览／导出、旧日语渲染与混合语言快照；schema 保持 7。

2026-10-16 重新打轴与日语字号修复（0.4.3.4，仅提升 hotfix）：顶部“重做”和打轴页“重做打点”均替换成“重新打轴”，确认弹窗默认不执行。确认后清空所有歌词行／单元时间、原始输入、完成标记及待应用／可重做打点，停播并回到歌曲起点与首个待打单元；保留全部已编辑原文、读音、罗马音、翻译、分组、语言元数据、ID／显示快照，不修改媒体、视频剪辑、节拍器或裁切。取消完全不改；存在未应用原文／快速编辑草稿时先要求处理；可撤销已应用时间的清空，临时打点不进入项目历史。Ctrl+Y 仍为普通项目重做，不绑定破坏性操作。日语句统一预留注音行高度，无汉字／无注音句的主字不再因高度适配而放大，主字基线与有注音句下行一致；长句横向适配仍保留。支持旧日语渲染、混合语言快照、罗马音模式与所有画幅；预览／导出共用。schema 保持 7。

2026-10-16 工作区裁切（0.4.3.3，仅提升 hotfix）：新增项目级可选 `WorkArea` 起止范围，使用原时间轴微秒，默认整首主歌曲。预览页可输入秒数或将播放头设为起止点，点击应用后生效，支持恢复全长、撤销／重做与保存／恢复。预览播放到终点暂停，再次播放从起点开始；暂停时允许浏览范围外内容以重新选区，打轴页始终保留完整歌曲。导出音频（含视频原声混音）、视频／图片、字幕与频谱统一截取该范围，输出从 0 开始；不改原文件、不改歌词打点、片段位置或节拍器偏移。范围须在主歌曲内且时长大于 0；换歌／移除主歌曲时重置，背景素材变化保留。手动裁切，不自动检测静音。schema 升至 7，旧项目默认完整歌曲，保存后继续使用新版。

2026-10-16 节拍器辅助语义（0.4.3.2，仅提升 hotfix）：节拍器不再是待应用打点会话的固定依赖。可在已有临时点／重做点时开启、关闭、修改 BPM／偏移／吸附细分、自动初始化及撤销／重做节拍设置；仅之后新敲入的点使用当前配置。细分支持每拍 1／2／3／4／6／8 格，默认整拍，不改变试听整拍声音；金色长线／蓝色短线显示整拍／细分。已应用、待应用与可重做点均保留原时间，重做恢复原值，不重新吸附。同一句允许自由打点与吸附混合；新点若吸附至上一点或更早位置，仍拒绝新点以避免零／负时长，不挪动旧点。自动初始化仍只填 BPM／偏移草稿，播放试听与导出规则不变。schema 升至 6 保存细分，旧项目默认每拍 1 格，不重写打轴。此规则取代早期“有临时打点不得修改节拍器”的限制。

2026-10-16 图片与画幅调整（0.4.3.1，仅提升 hotfix，build 保持 3）：接受被 FFmpeg 识别为 `image2` 的有效 PNG／JPEG／BMP，修复带 EXIF 的渐进式 JPG 导入误拒绝。扩展名、容器／编码、尺寸上限和单帧解码检查组合使用，不把视频容器或多帧 JPEG 当作静态图；图片源时长保持 0，片段默认 5 秒。图片改为等比例居中铺满并裁去超出边缘，视频仍保持原完整画面；频谱改为视频左下起点向上延伸。比例与分辨率独立选择：16:9／4:3／1:1／9:16，720p／1080p 按短边映射，具体像素表见 README；预览画布随设置变化并与导出一致，可撤销并持久化。字幕字号／注音／描边按短边缩放，下方 30% 双句布局保留。schema 仍为 5，沿用明确宽高，不改变原图或歌词时间。

2026-10-16 开发队列 R1／R2／R5／R6（0.4.3.0）：新增静态 PNG／JPEG／BMP 导入，复制至工作区并追加 5 秒片段，可拖动首尾调整时长、移动／分割／复制／拼接；图片不受源时长限制、不作为歌曲、不参与混音。统一规范化 PNG 用于预览和导出，保持比例不裁切，视频轨空隙黑场不变。预览右侧可开启浅蓝／浅黄 32 条频谱，默认关闭；原歌曲离线流式 FFT 预处理，播放只采样绘制，不改变音频和歌词时间，打轴页不渲染该动画，最长支持 4 小时。左侧素材名称旁提供三类矢量图标。字幕新增四套预设与本机字体搜索；默认未唱白字深蓝描边、已唱黄字白描边，日语注音／罗马音、标点和第三方显示快照共用逻辑。预设保留字体／布局、可继续精调，点击应用生效；缺字体显示回退信息但保留原名字。schema 升至 5，旧项目保持原样式和打轴，保存后继续用新版，旧版拒绝新格式以避免丢失新字段。Folia 与 osu! storyboard 仍为长期 TODO，未实现。

2026-10-16 录制热修复（0.4.2.1，仅提升 hotfix，build 保持 2）：自动识别模式下，部分英语句子依据歌曲上下文处理，已有正常单词单元，却因“建议确认语言”导致整首录制被阻止。按用户明确的一般规则，任何单纯语言识别不确定（含暂未确定语言）的结果，在已有完整可打分词时都只是建议；不阻止开始，实际录制到该句才显示可关闭的非模态 warning，不暂停播放、不拦截空格、不抢焦点。可自行确认／修正或直接忽略，忽略不改变语言、分词、已打时间，也不等同于人工锁定。日语缺必要读音、无效映射及插件分析／校验失败仍阻断。既有项目无需重导或重建，ID／时间／显示快照不变；schema 4 与现有插件构造接口保持兼容，以可选字段区分检测建议和实际阻断问题。

2026-10-16 收尾简化（0.4.2.0，取代早期多轨设计）：软件定位为歌词制作工具，白底与极淡浅蓝／浅黄边框，固定歌曲／声音、视频（可含原声）、字幕三条轨道，不提供增轨、换轨、合轨。项目素材允许移除：引用中素材先确认，可撤销，不物理删除工作区文件，不改变歌词打轴。新建项目以 `<项目名>.lrn` 作为配置入口，支持文件选择及命令行打开、完整工作区移动；格式升至 schema 4。用户明确不要求旧多轨兼容，不设计转换功能；文件含额外轨内容时拒绝加载而非丢弃内容。歌词获取页时间仅显示一位小数，保留内部精度。预览页增加单一项目级节拍器：BPM／首拍偏移、试听音频同步、开启时输入补偿后吸附最近拍点；不重新吸附已有时间、不导出节拍声，不允许待应用打点期间修改节拍配置。

版本策略：统一采用 `major.minor.build.hotfix` 四位版本号。`0.4.x.x` 为内部收尾阶段，计划以 `0.5.0.0` 作为首个对外开放版本；公开前仍需完成整曲／低配实机、分发许可与搜索服务客户端信息等验收。多个 BPM／timing point 等长期节奏辅助需求保留，不纳入本次。

2026-10-16 编辑流程补充（0.4.1，取代 0.3.6 的获取页只读约束）：歌词获取／预览页双击行原文进入行内编辑，可复制／粘贴，Enter 应用、Esc 取消；时间列不直接编辑。原文变化只重新分析本句，保留本句起止和其他句的时间，已打轴时确认清除本句逐单元打点。右键行可复制整行或在该行前／后插入；新句未打轴。如果插入处前后两句都有实际时长且前一句结束等于或晚于后一句开始，先以默认取消的确认框说明将清除新句及之后的行时间、单元时间、原始打点及打点确认，前一句结束保持不变；取消不修改项目，确认保留后续原文、读音、语言及显示映射并将打轴浏览句定位到新句。真实空隙、列表首尾、纯未打轴行插入保留已有时间。全部操作可撤销／重做，待应用／可重做录制点必须先处理；行内草稿不被自动保存为正式内容，显式保存可应用，关闭纳入保存／不保存／取消询问。格式继续使用 schema 3。

## 4. 功能需求

### 4.1 工作区与项目

创建项目时，用户必须选择一个新的或空的工作区目录。所有外部素材在导入时复制到工作区，项目运行时只引用工作区内的相对路径。

建议目录结构：

```text
工作区/
├─ <项目名>.lrn
├─ media/
│  ├─ audio/
│  ├─ video/
│  └─ images/
├─ lyrics/
├─ cache/
│  ├─ waveforms/
│  ├─ thumbnails/
│  └─ proxies/
└─ exports/
```

要求：

- `<项目名>.lrn` 使用带 `schemaVersion` 的 JSON，当前 schema 9，直接保存项目配置；
- 文件选择／命令行打开 `.lrn`，Windows 文件关联由用户选择或后续安装器配置，不在便携版启动时静默注册；
- 素材使用稳定 ID，显示名称与物理文件名分离；
- 移除素材清除项目引用及关联片段，使用中先确认；可撤销且保留歌词打轴，不物理删除素材文件；
- 同名文件自动生成唯一名称；
- 导入前检查磁盘空间，失败时清理未完成副本；
- 缓存可安全删除并重新生成；
- 整个工作区移动后仍可打开；
- 文件/文件夹选择按入口独立记忆：新建工作区、打开工作区、歌曲、视频、歌词和导出各自保存上次确认目录，取消不更新，重启后恢复；首次打开可定位到已创建的工作区，但不覆盖打开入口已有记录；
- 路径偏好存于当前 Windows 用户的本地应用数据目录，不随项目保存；失效路径退回可用上级目录，首次导出默认工作区 `exports/`；
- 保存采用“写入临时文件后原子替换”，避免异常退出损坏项目；
- 自动保存与崩溃恢复列入 MVP，但不能覆盖用户最后一次显式保存的恢复点；
- 后续可在此目录模型之上增加整包导出。

### 4.2 主时间基准

- 项目时间从 `00:00:00` 开始；
- 主歌曲音轨是唯一的主时钟；
- 默认项目终点和导出终点是主歌曲结束时间；
- 如果只导入歌曲视频，其音轨成为主歌曲音轨；
- 歌词、视频片段和预览播放都从属于主歌曲绝对时间；
- 内部时间使用整数 tick 或微秒，不能使用浮点秒作为持久化格式；
- UI 可按帧或毫秒展示，但数据不绑定特定导出帧率。
- 歌词获取／预览表格的开始／结束秒四舍五入到一位小数；显示取整不参与保存或打轴计算。

### 4.3 素材导入

正式支持：

- 音频：MP3、WAV；
- 视频：MP4；
- 歌词：TXT、LRC、SRT。

导入过程需要：复制文件、读取媒体信息、计算文件指纹、生成波形/缩略图缓存，并在必要时生成低分辨率代理视频。FLAC 和其他视频容器可以在底层支持时导入，但不作为 MVP 验收条件。

媒体工具的标准输出和错误输出固定按 UTF-8 解码，不依赖 Windows 系统／控制台代码页。中文、日文等文件名和内嵌标签不得导致媒体信息 JSON 解析失败；修复不重写原文件、标签或歌曲内容（0.4.5.2）。

### 4.4 歌词文档与编辑器

歌词编辑器支持：

- 新建、粘贴、导入和编辑歌词；
- 新增、删除、排序、合并和拆分歌词行；
- 编辑主文本、读音、罗马音和翻译辅助行；
- 合并、拆分、排序演唱单元；
- 建立显示范围与演唱单元的多对多映射；
- 标点默认不生成时间单元；
- 标记间奏、跳过、稍后处理和仅显示不扫色；
- 编辑操作进入统一撤销/重做历史。

双行内容类型必须显式区分：

- 原文 + 拼音；
- 原文 + 假名；
- 原文 + 罗马音；
- 原文 + 翻译。

主歌词拥有演唱时间；辅助行在 MVP 中跟随主歌词显示，不独立打轴。

### 4.4.1 联网搜索扩展（0.3.0）

“歌词获取 / 预览”页提供搜索窗口：所有语言通过 `ILyricSearchService` 的 LRCLIB 适配器检索候选版本并预览；已授权文本可由用户粘贴并记录来源。0.3.12 起不再提供 UtaTen 浏览器搜索入口。

只在点击搜索后发送歌名/歌手，不上传素材；不调用 AI、无 API Key。候选结果显示歌手、专辑、时长及是否包含行时间，用户确认后导入 TXT/LRC，替换现有歌词时再确认，进入撤销历史。保留原始歌词文件、来源 JSON 及项目中的 `LyricSource`。LRC 行时间不保证准确，也不作为 AI 对齐结果。

后台搜索可取消，超时 20 秒，顺序请求与 300 ms 间隔，短期内存缓存，尊重服务限流 Retry-After；响应和文本大小有上限。没有结果、断网或接口变化时可粘贴已授权文本或从本地文件导入，不自动重试、补写歌词或绕过网站限制。

AI 不用于当前检索；后续如需含糊歌名匹配、整理或翻译，按用户偏好优先评估 DeepSeek，但须单独明确数据发送和费用。本版不加入未实现的 AI 开关。

### 4.5 日文自动注音（原功能）

- 对歌词中的所有日文汉字生成假名读音；
- 假名保存到独立读音层，不改写主歌词；
- 从确认后的假名生成罗马音；
- 打轴前必须完成汉字假名读音，未识别的读音不得用于录制；罗马音仅为可选的小字参考，缺少罗马音不阻止按正确假名录制；
- 按演唱音节分组：拗音/小元音与前面的假名组合，促音 `っ`、拨音 `ん` 及长音符 `ー` 并入前一单元；普通大字元音保留单独单元，如 `じょ｜う`；
- 词典分词边界不能打断上述组合；`ヶ/ヵ` 根据校正后的读音拆分，不能因字形小而并入前字；
- 用户可以修改读音并合并或拆分演唱单元；
- 人名、地名、当て字和特殊唱法允许人工覆盖；
- 已确认或手工修改的读音不得被重新分析静默覆盖。

读音状态：

```text
generated  自动生成，待确认
confirmed  用户确认
manual     用户手工输入或修改
```

自动注音处理所有含汉字的词段，结果均可编辑，不承诺自动结果始终正确。首版内置 MeCab/IPADIC 离线词典；词典未收录的生僻字、专名和特殊唱法会保留原文作为待校对占位，必须人工填写假名，不把占位视为正确注音。

0.3.3 分组示例：`一緒 → いっ｜しょ`；`戦場ヶ原 → せんじょうがはら → せん｜じょ｜う｜が｜は｜ら`；`ちゃん`、`ディ` 各为一个单元。0.3.4 修正：录制始终以假名为准，假名在上、原文在下，共享汉字只显示一次，罗马音为默认隐藏的小字参考。手改整句假名同步重建打轴单元，汉字词组保持可编辑的显示映射。旧项目保留现有时间，可选中行“按语言重新分组”采用新规则；已打轴的行重新分组前提示并提供撤销。

### 4.7 手动打轴工作台

0.3.1 修正：卡拉 OK 逐字/日语音拍是默认和主要工作流；无需先逐行打轴。一空格对应一个演唱单元，按提示条依次记录，自动跨句，可用 Enter 在完整句末记录尾字结束并应用，也可整曲录完后额外一空格记录结束点。退格/重做按单元跨句推进。未完成句不能用均分补齐冒充精确时间，未录后续句保持原数据。

支持两种精度：

1. 逐单元打轴（默认）：按中文字、英文单词或日语演唱音节记录入口和尾字结束，连续跨句；
2. 逐行打轴（辅助）：记录每行入口，仅用于快速草稿，不作为逐字录制的前置要求。

录制界面至少显示当前行、上一行、后续一至两行、当前等待单元、音频波形、播放头、已记录时间点、歌曲进度和醒目的录制状态。

0.3.4 录制显示规则覆盖上述多行建议：只显示当前句与下一句两行，长句保持同行横向滚动并跟随待录单元，跨句时整体推进，退格时可以回到上一句。点击单元后可在它前面换行，或把该句与下一句合并，保留读音映射、单元时间及未应用打点；操作暂停播放，可继续录制或撤销/重做。

默认快捷键：

| 按键 | 行为 |
|---|---|
| 空格 | 记录下一歌词单元 |
| 退格 | 撤销最近一次记录，播放不中断 |
| Esc | 暂停或退出录制状态 |
| Enter | 完成当前行/区间 |
| 左/右 | 小幅回退/前进 |

必须支持：

- 无中断撤销与重做；
- 只重录选中行或区间；
- 从目标前 2–5 秒倒数进入；
- 0.5×、0.75×、1×播放，尽量保持音高；
- 区间循环；
- 全局输入延迟补偿；
- 拖动、方向键微调、批量移动和整行偏移；
- 跳过、稍后处理和回退上一行。

### 4.7.1 项目节拍器（0.4.2.0）

- 单组项目级配置，默认关闭，BPM 120，首拍偏移 0 ms；BPM 支持 20–400 小数，偏移为 ±600000 ms 内整数。
- 预览页可开启／关闭并应用 BPM／偏移／吸附细分（每拍 1／2／3／4／6／8 格）；正偏移延后第一拍，负偏移将第一拍置于歌曲开始之前。只使用歌曲区间内的有效网格点。
- 节拍声在歌曲试听输出链路合成，共享设备时钟；暂停、跳转、循环及保音高变速跟随歌曲，不使用 UI 定时器发声。
- 开启时，打点先输入延迟补偿再吸附最近拍点；正中间取后一拍。原始按键时间保留，同拍重复点或范围内无有效拍点明确拒绝，不产生零长度单元。
- 歌曲最后不足一拍时，终止点允许使用歌曲真实终点（Enter 或完整录制后的额外空格），演唱入口仍遵循拍点规则。
- 仅影响新打点；已有待应用／可重做打点也允许修改配置及撤销／重做节拍设置，旧点保持原时间，重做旧点不重新吸附。
- 设置保存入项目及恢复文件，支持撤销／重做；节拍声按整拍用于试听，不随吸附细分加快，不写入导出媒体。多个 timing point／拍号留作后续扩展。

### 4.8 视频时间轴

2026-10-16 按歌词制作工具定位简化：固定一条歌曲／声音轨、一条可含原声的视频轨、一条字幕轨；视频片段不能重叠。取代 2026-10-13 的多轨方案，未公开发布阶段不提供旧多轨转换。

- 移动、复制、删除视频片段；
- 左右拖动、片段吸附、播放头处分割；
- “顺序拼接”按原开始时间紧密排列视频片段，支持撤销；
- 裁切片段头尾；
- 顺序拼接多个片段；
- 片段允许重排和存在间隙；
- 每个片段提供独立静音开关；
- 视频原声在裁切、移动时与画面保持绑定；
- 背景视频默认静音，作为歌曲视频导入的主素材默认不静音；
- 主歌曲与启用的视频片段原声可以同时播放。
- 主歌曲轨独立；视频原声包含在视频轨，不额外展开音轨，裁切／移动保持一致；不提供多歌曲剪辑。

首版不提供独立音量曲线、淡入淡出或效果器。若视频轨在歌曲范围内没有片段，该区间预览和导出为纯黑画面，歌曲与字幕继续播放。视频超出歌曲终点的内容默认不导出。

空白区间必须作为明确的时间范围存在，以便后续 AI 生成的视频作为普通片段填入。MVP 不显示不可用的 AI 入口。

### 4.9 字幕布局与渲染

从 0.4.6.0 起取消下方 30% 的固定限制。仍同时显示两句、左上和右下交替成为当前行，整体从画面底部随字号向上扩展。字号不再受 30% 区域压缩；仅在文本超宽或两行超过整个画面可用高度时等比缩小。横屏、竖屏、方形和 4:3 使用相同规则。旧工程的 SafeAreaRatio 字段为兼容读写保留，不再参与渲染；工程 schema 仍为 9。

- 字幕区域默认透明，不遮盖视频；
- 当前行按单元连续扫色，下一行保持未激活颜色；
- 当前行结束后，下一行激活，空出的位置载入后续歌词；
- 支持字体、字号、未激活色、激活色、描边、阴影、行距和区域边距；
- 用户不能自由拖动行位置；
- 主歌词与辅助行需要独立字号，但作为一个布局单元移动；
- 预览和导出必须调用同一个排版及字幕绘制核心。

字幕选色（0.4.6.1）：四个文字／描边颜色项显示色块、可编辑色号及复制按钮。点击色块打开二维饱和度／亮度调色盘，配合色相、不透明度滑块和常用颜色；支持键盘微调、还原和取消，取消不改原参数。可复制粘贴 `#RRGGBB`／`#AARRGGBB`（可省略 `#`），AA 为透明度；写入时规范化，棋盘底纹用于预览透明色。无效输入明确提示且不能应用，已唱描边留空仍表示沿用未唱描边。预设调用、全局样式保存及工程读写保持一致，schema 不变。

常用字幕样式与全局偏好（0.4.6.0）：

- 字幕样式页可以命名保存完整参数、调用、确认覆盖同名样式及删除；内置配色样式仍保留。
- 保存常用样式不直接改写工程；调用先填入编辑参数，沿用样式页现有的应用、工程保存及自动恢复点收集流程。点击“应用字幕样式”可立即预览。工程保留样式值，不依赖全局预设 ID，删除或覆盖预设不影响已应用的工程。
- 全局配置 `user-preferences.json` 位于 EXE 同目录，首次保存常用样式时创建，可随便携软件搬迁。跨工程共享，与 `.lrn` 及工作区恢复文件分离。
- 配置 schema 为 1，保存 `subtitleStyles`；预留 `apiConnections` 的 endpoint/model/credentialReference 元数据。未来 API Key 应由独立安全存储保护，此文件只记录引用；本版未实现 AI 配置、密钥输入或密钥存储。
- 写入采用独占锁、临时文件和原子替换，上次成功配置留作 `.bak`。无法写入程序目录时显示权限提示，不静默改到其他目录；损坏或不支持的配置不自动清空覆盖，内置样式继续可用。更新软件时用户需保留自己的配置文件，不随发行包分发个人配置。

### 4.10 预览与导出

预览：

- 目标刷新率为 24 fps；
- 音频为主时钟，视频帧、播放头和字幕追随音频时间；
- 性能不足时降低视频预览分辨率或使用代理，不改变最终导出；
- 允许偶发预览掉帧，但不能让音频或时间轴时钟累计漂移；
- 空视频区间显示黑色。

导出：

- MP4 容器、H.264 视频；
- 16:9、4:3、1:1、9:16；独立选择 720p／1080p，按短边映射，最大为 1920×1080 或 1080×1920；
- 24、30、60 fps；
- 包含背景画面、主歌曲、启用的视频原声和字幕；
- 离线渲染，不要求实时速度；
- 导出进度可取消，取消后清理不完整输出；
- 相同时间点的字幕排版与预览一致。

## 5. 非功能需求

### 5.1 兼容性目标

“十年内电脑可使用”定义为硬件兼容目标，而不是承诺支持已经停止维护的 Windows 版本。

MVP 正式支持：

- Windows 11 x64；
- 仍处于厂商支持期的 Windows 10 Enterprise/LTSC x64，可作为兼容测试目标；
- 8 GB 内存最低、16 GB 推荐；
- 支持 DirectX 11 的显卡；
- 无独立显卡也可运行，但允许降低预览质量和延长导出时间。

首版只发布 x64。ARM64 和 x86 不作为 MVP 发布目标。

### 5.2 性能与可靠性

- 1080p 项目在推荐配置上以 24 fps 为预览目标；
- 长时间播放时音画累计漂移应可检测并纠正；
- 时间轴交互不能因波形或缩略图生成而阻塞 UI；
- 所有缓存、分析和导出任务在后台执行并支持取消；
- 项目保存、素材复制和导出必须报告明确错误；
- 时间编辑、歌词编辑和片段编辑使用统一可撤销命令系统。

### 5.3 可测试性

- 数据模型、歌词拆分、时间约束和项目迁移可无 UI 单元测试；
- 字幕渲染支持固定时间点的图像快照测试；
- 导出后用探测工具验证分辨率、帧率、时长和流信息；
- 使用至少一台低配设备做端到端性能测试；
- 日文测试集必须包含组合假名、促音、长音、熟字训、人名和当て字。

## 6. C# 技术栈评估

### 6.1 结论

C# 适合此项目。推荐使用 **.NET 10 LTS + WPF** 构建客户端，把媒体解码、同步、字幕绘制和导出放在独立模块中，不让核心业务依赖 WPF 控件。

.NET 10 是当前 LTS，支持至 2028 年 11 月。WPF 是成熟的 Windows 专用 .NET UI 框架，具备 XAML、数据绑定、样式、模板、2D 图形和硬件加速等能力。虽然微软将 WinUI 3 作为新 Windows 应用的通用推荐，但本项目包含高密度时间轴、键盘工作流、大量自绘和原生媒体互操作；WPF 的成熟度、工具生态和部署可控性对 MVP 更有价值。

### 6.2 方案比较

| 方案 | 优点 | 主要代价 | 结论 |
|---|---|---|---|
| .NET 10 + WPF | 成熟、资料多、数据绑定和自定义控件稳定、原生互操作成熟 | 默认外观较传统；复杂画布仍需自绘 | 推荐 |
| .NET 10 + WinUI 3 | 现代 Fluent 外观，微软对新通用 Windows 应用的主要推荐 | Windows App SDK 部署和版本层更复杂；高密度编辑器仍需大量自绘 | 可选但不作为 MVP 首选 |
| C# + Avalonia | 跨平台、XAML 风格 | 当前明确只做 Windows；多媒体互操作和发布测试面扩大 | 暂不采用 |

### 6.3 推荐依赖

- UI：WPF on .NET 10；
- 架构：Domain / Application / Infrastructure / WPF App 分层，界面使用可绑定编辑行和局部窗口控制器；MVP 未引入额外 MVVM/DI 框架；
- 日志：工作区 `logs/application.log`，错误同时在界面呈现；
- 项目序列化：`System.Text.Json`；
- 2D 字幕和时间轴绘制：WPF 绘图核心（具体实现见 7.2）；
- 音频输出与主时钟：`NAudio.Wasapi`；
- 媒体探测、代理、波形提取和最终编码：固定版本的 `ffprobe`/`ffmpeg` 子进程；
- 测试：xUnit；
- 日文读音：`IJapaneseReadingService` + `LibNMeCab.IpaDicBin 0.10.0`，词典随包部署，无需日语语音包；
- 媒体工具：Gyan FFmpeg 8.1.2 essentials，版本和 SHA256 固定在 `scripts/media-toolchain.json`。

第三方依赖版本必须由集中包管理锁定。FFmpeg 大部分代码使用 LGPL，但启用部分可选组件后整体会受 GPL 约束；发布前必须固定构建来源、配置和许可证清单，不能随意从网络下载未知构建。

## 7. 推荐运行架构

```text
WPF Shell / Views
        ↓
Application（用例、命令、撤销、任务调度）
        ↓
Domain（项目、歌词、时间轴、样式；无 UI/媒体依赖）
   ↙          ↓             ↘
Workspace   Playback       Rendering
   ↓          ↓             ↓
文件系统   NAudio + 视频   WPF 共用字幕核心
              ↓             ↓
           主音频时钟  ← 统一时间采样
                    ↓
             FFmpeg Export Pipeline
```

关键原则：

- 主音频时钟是播放状态的唯一真相；
- 视频在预览时静音显示，其音轨预先解码/缓存后由音频混音层播放，从而避免两个播放器各自走时钟；
- 视频层根据主时钟选择当前片段并纠正 seek 漂移；
- 字幕渲染器输入“时间 + 布局尺寸 + 歌词数据 + 样式”，输出画面，不读取 UI 状态；
- 预览与导出共用字幕布局和绘制代码；
- FFmpeg 只通过接口暴露，不让命令行字符串散落在业务层；
- 日文分析器可替换，用户确认的数据与具体词典实现无关。

### 7.1 播放技术风险

WPF 自带媒体能力底层依赖 Windows Media Foundation，适合先验证 MP4 视频显示；音频由 WASAPI 播放并充当主时钟。微软没有为 Media Foundation 提供官方托管 API，因此不能在未验证的情况下承诺它足以承担最终精确播放器。

首个 PoC 必须验证：

1. 连续播放 10 分钟的音画漂移；
2. seek、循环和 0.5×/0.75×/1×变速；
3. 片段切换与黑场间隙；
4. 视频原声抽取后与主歌曲混音；
5. 低配设备上的 1080p/24 fps；
6. 中文、日文字幕的预览与离线帧像素一致性。

若 WPF/Media Foundation 视频层无法满足同步要求，只替换 `IVideoPreviewBackend` 为 FFmpeg/Direct3D 实现，不改动领域模型和编辑器。

### 7.2 当前字幕绘制实现（2026-10-12）

字幕 MVP 当前采用 WPF 的 `FormattedText`、字形几何和离线 `RenderTargetBitmap`，尚未引入 SkiaSharp。此选择沿用现有桌面框架的中日文字体回退和排版能力，减少当前依赖；后续可以通过字幕帧接口替换具体绘制器。

- `Application.Rendering.SubtitleSceneBuilder`：纯数据计算两句的显示位置、演唱单元进度、共享汉字词组映射和辅助行进度；不依赖 WPF。
- `Infrastructure.Rendering.WpfSubtitlePainter`：主歌词及辅助行排版、描边、阴影、按显示范围连续填色；预览与离线输出共用。
- `App.Controls.SubtitleOverlay`：在当前项目输出宽高的逻辑画布上调用共同绘制器，预览画布等比缩放，横竖屏均与导出一致。
- `Infrastructure.Rendering.WpfSubtitleFrameRenderer`：独立 STA 渲染线程，通过同一绘制器生成最大 1080p 的字幕帧，并转换为直通 Alpha 的 BGRA 像素。

字幕按字号从底部向上扩展，左上与右下两个位置轮流成为当前句，不再限制在下方 30%。辅助行置于主歌词上方；可选择不显示、假名、拼音、罗马音或翻译。仅当超出画面宽度或双行可用高度时整体缩小，不增加自由拖动布局。

0.3.4 日语显示规则：默认只在汉字词组上方标小字假名；项目级 `ShowRomanization` 默认 false，开启时改为在对应汉字/假名原文上方标罗马音，不叠加假名注音。按单元的显示范围合并共享词组，为注音预留宽度防止挤叠，注音高亮跟随对应原文范围。打轴与样式页开关同步，保存/重开后恢复，预览及导出一致。中英文保留既有辅助行规则。

自动检查已覆盖共享汉字词组的多音拍扫色、辅助行进度、精确时间边界的交替、间隙与间奏、禁用扫色、透明帧、字幕区域边界、小字号注音可见性和跳转后的帧一致性。研发 PNG 快照仅用于测试，未作为对外字幕素材导出功能提供。完整 MP4 合成已实现并经过真实编码/探测测试，低配设备性能仍待统一人工验收。

## 11. MVP 实现决策与统一验收

本版采用以下固定实现：

1. 中文拼音手工编辑；日文通过内置词典生成初始假名和罗马音，用户校对；
2. 辅助行在主歌词上方，字幕随字号从底部向上扩展、无 30% 限制，双句左上/右下交替；
3. 视频原声仅提供静音开关，与主歌曲混合并限幅；
4. 视频轨支持静态图片和视频，无片段时为黑底；可选频谱与字幕叠加在背景上，不提供 AI 背景入口；
5. H.264 使用项目预设码率编码，不开放高级编码器参数；
6. 20 秒自动保存到独立 `project.recovery.kfp`，不覆盖最后一次显式保存的 `.lrn` 项目入口（旧单轨项目仍可使用 `project.kfp`）；
7. 发布为 Windows x64 自包含便携 ZIP；这是软件发布包，不是后续版本的工作区打包功能；
8. 实际程序集为 App、Application、Domain、Infrastructure，按第 8 节职责分命名空间；测试对应四个程序集。

### 11.2 统一人工验收清单

- [ ] 用自有中日歌曲创建工作区，导入 TXT/LRC/SRT、音频和多个 MP4；
- [ ] 校对熟字训、人名、当て字及未收录汉字；修改读音/罗马音/显示映射，保存重开后不丢失；
- [ ] 逐行后逐单元打轴，验证打点撤销/重做、三秒进入、循环、变速、补偿和局部重录；
- [ ] 拖动/裁切/拼接片段，检查静音开关与间隙黑场；
- [ ] 连续播放至少 10 分钟，反复 seek，检查视频与歌词同步；
- [ ] 修改项目后等待自动保存，以任务管理器退出，再打开并恢复；确认显式保存版本仍可单独使用；
- [ ] 移动完整工作区到其他目录后打开；
- [ ] `.lrn` 文件选择／命令行打开、保存重开与 Windows“打开方式”关联；
- [ ] 移除使用中的素材、取消移除及撤销，确认歌词打轴保留且物理文件未删除；
- [ ] 节拍器正／负偏移、慢速／跳转、同拍拒绝、保存重开与导出无节拍声；
- [ ] 浅色布局在常用窗口大小可访问，确认三轨和一位小数显示不改变真实时间；
- [ ] 导出整首 1080p 的 24/30/60 fps 视频，检查首尾、扫色、日文小字、混音和视频边界；
- [ ] 导出中取消、磁盘空间不足和素材缺失时，确认提示及输出清理；
- [ ] 在另一台接近最低配置的 Windows x64 设备上运行便携包，记录实际预览帧率及导出耗时。
