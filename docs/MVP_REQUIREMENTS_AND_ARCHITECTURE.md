## 1. 产品定义

2026-10-30 AI 集成分支（优先于下方 AI 占位阶段描述，基于 0.5.1.0，尚未发布）：接入 Pi agent-core 1.4.0 与 Cordis 3.18.1。WPF 通过私有标准输入/输出调用随包的 Node 22.23.4 host；Pi 管理单次 agent 循环，Cordis 管理适配器服务和聊天插件生命周期。不加载项目插件或暴露文件、Shell、项目编辑工具。

- 内置 DeepSeek、ChatGPT/OpenAI、Claude、Kimi、Qwen 官方模型预设；模型下拉框允许输入自定义 model。选择预设自动填配置名称、协议，官方来源自动填完整 endpoint；代理地址可自行编辑。OpenAI chat/completions 为通用协议，DeepSeek 使用其兼容协议和 thinking 扩展，Claude 官方使用 Messages 协议。请求完整地址原样使用，不自动追加路径，不跟随携带凭据的重定向。调用只允许 HTTPS 或本机 HTTP。
- 凭据字段按适配器需求显示：没有模型时隐藏，当前五家预设均只显示 APIKey。已有 AK/SK 加密值保留，但本阶段没有 AK/SK 签名适配器，不把这两项作为 APIKey 替代。配置新增可选 model/providerId/protocol，旧配置保留，选择模型后可继续使用；偏好 schema 仍为 1。
- 配置页不显示内部字段名前缀或 true/false；“联通测试”位于保存左侧，通过同一运行时发送一条短请求并验证完整流式响应。保存按钮未测深灰/白字、成功绿色、失败黄色；修改配置或切换配置清除测试状态，测试结果不作为跨启动的永久可用保证。未测试或失败仍允许保存，保存本身不发网络请求。
- 聊天选择已保存配置、Enter 发送、Shift+Enter 换行、停止取消当前请求。正文与返回的 thinking/reasoning_content 分区流式更新，思考区在正文前默认展开，收到首个非空白正文片段后自动折叠一次，之后用户可手动展开，后续正文不再次强制折叠；没有思考返回则不显示。思考内容先按句缓冲检查，再进入界面；系统提示原文片段及明显的系统/开发者指令引用会被隐藏，检测后本轮其余思考也隐藏。此过滤不构成保密边界，不能保证识别所有翻译或语义转述，系统提示中不应存放秘密。OpenAI Chat Completions 不保证返回可显示的思考内容。聊天上下文仅内存保存；切换/修改连接和“新对话”清空上下文，避免不同服务商间无意传递对话；收起不停止，关闭应用停止。只发送用户在聊天中输入的内容和本会话成功回复，不自动附加项目、歌词、音频、APIKey 或路径。
- 本次不实现自动读音修正、自动打轴、工作流、MCP 或业务工具。凭据保留 DPAPI，子进程参数/文件/日志中不写密钥，临时明文仅通过私有 stdin 交给执行请求的 host。上下文和回复有上限，请求可取消且有超时；失败/半截回复不会进入下一轮历史。
- 开发运行前执行 `scripts/bootstrap-ai.ps1`；版本/哈希与 npm lock 固定，离线测试使用模拟响应与 loopback 服务，不消费真实密钥。发布脚本自带 Node 和打包 host，不依赖用户安装 npm/Node；许可随包保留。主程序既有制作/导出功能保持离线独立。

接口依据（2026-10-30 核对，模型权限与地区由各家账户决定）：[OpenAI Streaming](https://developers.openai.com/api/docs/guides/streaming-responses)、[DeepSeek](https://api-docs.deepseek.com/)、[Claude Messages](https://platform.claude.com/docs/en/api/messages/create)、[Kimi](https://platform.kimi.ai/docs/get-your-api-key)、[Qwen OpenAI 兼容](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)。预设可编辑以应对模型更新/地域差异。

以下为 2026-10-28 AI 界面占位阶段记录，其“不接入模型”条目由上述 2026-10-30 决策替代：

- 顶部右侧“AI 助手”使用用户提供的图标并保留文字，另有“AI 配置”入口；客户端内使用用户提供的莉拉桌宠替代可拖动按钮。单击桌宠切换展开 / 收起对话框，顶部助手入口仅展开；拖动不切换。桌宠只在客户端内显示，不创建桌面悬浮窗口；拖动限制在客户区，捕获丢失取消点击，窗口缩小时位置钳制到可见范围。
- 桌宠动画来自用户 `lila-desktop-pet-animations.zip`：idle-blink 待机，trot 拖动，happy-hop 点击反馈后回到待机。使用原始透明 PNG 帧并对相同文件内容去重，不运行包内脚本，不依赖 Live2D / 浏览器 / 新外部运行时。36 张独立帧还原 92 帧序列及原始 70 / 80 ms 节奏，按 256 像素宽度后台解码并冻结共享；计时器只切换图片。不可见、窗口最小化、卸载或系统关闭客户区动画时停止动画计时，静态图片仍可开关聊天。动画不进入成片、不依赖歌曲时钟，也不表示模型已接入。
- 聊天层在预览页覆盖右侧功能区并与其同宽，内部边缘留白、圆角卡片及独立背景阴影强调悬浮感，不重新排布预览和时间轴；其余编辑页在相同右侧位置显示浮层。小窗口自动缩短输入区。收起显示底层原功能，当前进程内保留消息与未发送草稿；不等于取消任务或禁用 AI。输入框 Enter 发送、Shift+Enter 换行，不触发播放或打轴快捷键。
- “用户 AI 配置”是独立窗口，无需打开工程即可新增、编辑、删除多个连接。配置名称 `providerName` 必填、1–80 字符且不区分大小写唯一；`isOfficial` 必须显式选择官方（true）或供应商 / 中转站（false）。`apiPath`、`APIKey`、`AK`、`SK` 均可留空，允许独立填写或同时保存。填写 apiPath 时须为 HTTP / HTTPS 完整地址；不在地址中嵌入用户名密码。
- APIKey / AK / SK 使用密码框，保存时通过 Windows DPAPI CurrentUser 加密后写入 EXE 同目录 `user-preferences.json` 的 `aiProviders`；明文凭据不写入该文件、备份、工程或日志。跨机器 / Windows 用户搬迁后，元数据可读，凭据需重新填写，并显式确认替换不能解密的内容。不会静默把解密失败当作空凭据保存。
- 全局偏好 schema 保持 1（新增可选集合），保留已有字幕样式、角色、旧 `apiConnections` 和扩展字段，继续使用独占锁与原子替换。配置编辑有未保存修改时，切换 / 新增 / 关闭先提示；删除需确认。此阶段没有连接测试、默认模型选择、协议适配、AK/SK 签名或工作流；保存不同厂商的配置不代表已经兼容其调用协议。

2026-10-21 发布收敛（0.5.0.0，优先于下方历史记录）：移除 E 烟花可视化，仅提供 A 经典左下、B 底部密集、C 居中白色、D 自旋环形四种样式。旧工程的 Fireworks 值仅保留用于无损读取／保存，不渲染、不生成频谱缓存；界面提示已停用，可选择 A–D 或重新开启使用 A。不静默替换旧工程样式，不改素材和歌词打点。节拍器导航及整块设置区隐藏，保留底层代码与工程 BPM／offset／细分配置，但当前公开界面不发节拍声、不吸附新打点；已录入的时间不变。右侧可见导航依次为生成伴奏、曲名显示、可视化、角色控制。schema 仍为 11；便携包版本为 0.5.0.0，打包不等于自动向远程发布。

2026-10-13 品牌决定（0.3.7）：中文名“莉拉OK!”，英文名“Liraoke”（呼应 karaoke），使用用户提供的浅蓝背景人物图片作为 Windows 图标。保留原画，封装多尺寸 ICO；启动文件和便携包采用 Liraoke 名称。原有工作区格式及本地设置目录不变，内部工程名 KaraokeFilmMaker 暂时保留。

KaraokeFilmMaker 是一款面向普通创作者的 Windows 卡拉 OK 风视频制作工具。用户将歌曲、歌词与视频素材导入独立工作区，通过内置歌词编辑器和手动打轴工作台制作按中文字、英文单词或日语演唱音节高亮的字幕，最后导出已经合成背景、歌曲和字幕的 MP4 视频。

MVP 的核心价值是：

1. 中文、日文歌词可以方便地编辑、注音和校准；
2. 即使不使用 AI，也能独立完成整首歌曲；
3. 按错可以立即撤销，任意区间可以局部重录；
4. 预览与最终导出的字幕布局和时序保持一致；
5. 项目及其素材全部包含在可移动的工作区目录内。

## 2. MVP 范围

2026-10-21 相邻句尾音重叠（0.4.7.1）：以打轴界面的一行为一句，句内入口仍严格递增，句序入口也保持先后；相邻两句允许重叠，但第一句未结束前不得开始第三句，不允许跨行重叠。只有完整录完一句后使用 Enter／结束并应用明确收尾，才保存该句的 `ExplicitEndTime`，允许后一句覆盖它的尾音。操作方式为前句收尾后回退播放位置，继续录下一句；不会压短、覆盖或重排上一句已经保存的点。一批连续打点中自动衔接的中间句不具有明确收尾记录，只有最终收尾句具备。冲突入口拒绝加入，应用时再次校验，重录也不能越过后续保留的句子或制造三句重叠。保存与恢复保留收尾点、单位 ID 和原始敲击时间。项目 schema 升至 11；旧项目保留所有时间但不猜测历史 Enter，需重录并明确收尾后才能新增重叠。

重叠显示：预览和 MP4 共用场景，在两句同时演唱时保留两句及各自的扫色进度、原有上下交替槽位，不用后一句取代前一句，不预显第三句占用仍在演唱的槽位。每句仍在开始前六秒以内预显，到自身明确结束时间移除；暂停／跳转／变速及裁切导出都使用原歌曲时钟。清空／重新计时／重新分析会清除失效的明确收尾记录；按既有单元换行只让右句继承原终点，整体偏移同步移动；不能把重叠两句直接合成句内冲突的单元。修复打轴原文显示将部分重叠汉字范围重复拼接的问题，例如“帰”与“帰っ”合并显示为“帰っ”，不修改导入原文、读音或已打时间。

2026-10-21 预览布局（0.4.7.1）：横屏和方形工程的预览框遵守输出画幅比例；竖屏工程使用 1∶1 预览框，内部按真实竖屏画布等比例完整显示，保留左右留白，不改变导出、不裁切或拉伸。右侧改为一个连续滚动页面，导航标签从上到下依次为“生成伴奏／曲名显示／可视化／角色控制／节拍器”，点击只滚动到对应分区，草稿控件不被重建。淡黄和淡蓝背景交替区分功能，可视化不再隶属于节拍器；节拍器降至最后，保留原有手动设置与实验性自动初始化，本次不改检测算法。伴奏区新增生成按钮，与顶部制作伴奏共用流程及忙碌／无歌曲禁用条件。原视频／图片片段精调保留为页面末尾折叠项。小窗口和纵向导航可访问所有分区，切换到打轴页恢复原媒体监视器，不使用预览框的固定尺寸。

2026-10-20 曲名与角色工作流（0.4.7.0）：预览右侧新增“曲名显示”和“角色控制”。曲名默认关闭，启用后默认跟随主歌曲文件名（无扩展名），可独立编辑文本、左／右上角、字体、字号、文字／描边颜色及阴影，预览和导出共用绘制。打轴页歌词浏览区域约占左侧内容区的 80%（不含状态栏／播放按钮），按窗口高度显示更多句，滚轮翻页、当前句自动跟随；只构建可见页，不为整首歌持续绘制动画。

工程可创建命名角色，每个角色保存完整字幕样式；字幕样式页选择“标准”或具体角色编辑，切换对象前应用当前有效参数。可显式保存角色及样式到程序根目录 `user-preferences.json`，新工程从常用角色复制创建独立角色，修改／覆盖预设不追溯修改其他工程。打轴页点击“整句”或演唱单元，Ctrl 增减、Shift 连续选择；触发多选后禁用单字读音及相关编辑，普通单击恢复。无选择时角色分配作用于当前浏览句；勾选多个角色表示合唱，不勾选表示标准。单位级设置优先于整句：null 继承、空数组显式标准；“恢复整句角色”清除单位覆盖。整句重新分配同时清除其单位覆盖，混合勾选的中间态保留各对象已有角色。删除角色只移除其引用，不改歌词和打点；可撤销。分组、换行／合并保留或按原文范围迁移角色。

合唱仅显示一份文字，按工程角色顺序从上到下等分色带：AB 为上 A 下 B，三人则三段；文字、注音及未唱／已唱描边同步分色。第一个角色决定共享字形的字体、字号、描边宽度、阴影及注音模式；各角色提供各自未唱／已唱颜色。共享汉字映射内部的多个演唱单元若分配不同角色，共用书写组取角色并集显示，不复制或拆坏字形。区域边距与两句槽位为工程级布局参数。项目 schema 升至 10；旧工程迁移后无角色、曲名关闭，原歌词／时间／伴奏映射不变；旧软件应拒绝新 schema，避免丢失配置。

标点连续扫色：未单独映射的标点与前一个书写／演唱组共享完整时间和扫色范围，句首标点归第一个组，句尾标点在最后一个组的时间内扫完；不新增演唱单元、不改变原始敲击或已保存时间。词内标点保留原有单词映射；空白／未映射的普通字不被吞并。此条替代此前在下一个词开始或最后一个词结束时瞬间将标点标黄的行为。

2026-10-19 伴奏工作流优化（0.4.5.1）：伴奏不再作为素材导入或替换主歌曲，成功后写入工作区 `accompaniments/`，工程以原素材 ID、内容哈希和时长保存对应关系。schema 升至 9，旧工程空映射迁移，不猜测既有分离音频的来源。预览右侧新增“伴奏”Tab，仅提供试听开关；默认关闭，打轴始终用原歌曲，导出独立选择。导出先用复选框选择原唱和／或伴奏，再选择文件名，分别追加 ` -on vocal-`／` -off vocal-`，覆盖前确认；取消保留并提示已完成版本。主歌曲来自视频时，伴奏模式也将相同素材的移位／裁切片段路由至伴奏，不修改片段静音配置，其他视频原声不变。工具栏依次为新建／打开／制作伴奏／撤销／保存／导出／取消；“重新打轴”仅保留在打轴页播放按钮右侧。重新制作失败或取消保留旧关联，旧伴奏文件保留供撤销使用，文件丢失时禁用伴奏试听／导出并提示重新制作。此条替代 0.4.5.0 的素材导入、主歌曲替换及仅人声输出交互，安装与推理逻辑不变。

2026-10-13 编辑流程更新（0.3.6）：原“歌词编辑”页改为“歌词获取 / 预览”，只负责搜索、文件挂载及只读内容预览；语言选择用于新获取内容，不能无意改写已挂载歌词语言。实际修改集中在打轴页：双句窗口通过鼠标滚轮遍历全部歌词，浏览行以稳定 ID 记录，不修改音频位置或录制游标；只绘制可见两句。显式返回或再次打点恢复跟随，另设“从浏览句开始打轴”控制起点。快速单元修改、换行/合并，以及整句文字/读音/翻译/时间/标志编辑、单元精修、增删/句序/重新分组均在打轴上下文中发起。影响单元结构的操作须先处理待应用打点，不能静默丢失录制数据。

## 4. 功能需求

### 4.1 工作区与项目

创建项目时，用户必须选择一个新的或空的工作区目录。所有外部素材在导入时复制到工作区，项目运行时只引用工作区内的相对路径。

建议目录结构：

```text
工作区/
├─ <项目名>.lrn
├─ media/
│  ├─ audio/
│  ├─ video/
│  └─ images/
├─ lyrics/
├─ cache/
│  ├─ waveforms/
│  ├─ thumbnails/
│  └─ proxies/
└─ exports/
```

要求：

- `<项目名>.lrn` 使用带 `schemaVersion` 的 JSON，当前 schema 10，直接保存项目配置；
- 文件选择／命令行打开 `.lrn`，Windows 文件关联由用户选择或后续安装器配置，不在便携版启动时静默注册；
- 素材使用稳定 ID，显示名称与物理文件名分离；
- 移除素材清除项目引用及关联片段，使用中先确认；可撤销且保留歌词打轴，不物理删除素材文件；
- 同名文件自动生成唯一名称；
- 导入前检查磁盘空间，失败时清理未完成副本；
- 缓存可安全删除并重新生成；
- 整个工作区移动后仍可打开；
- 文件/文件夹选择按入口独立记忆：新建工作区、打开工作区、歌曲、视频、歌词和导出各自保存上次确认目录，取消不更新，重启后恢复；首次打开可定位到已创建的工作区，但不覆盖打开入口已有记录；
- 路径偏好存于当前 Windows 用户的本地应用数据目录，不随项目保存；失效路径退回可用上级目录，首次导出默认工作区 `exports/`；
- 保存采用“写入临时文件后原子替换”，避免异常退出损坏项目；
- 自动保存与崩溃恢复列入 MVP，但不能覆盖用户最后一次显式保存的恢复点；
- 后续可在此目录模型之上增加整包导出。

### 4.2 主时间基准

- 项目时间从 `00:00:00` 开始；
- 主歌曲音轨是唯一的主时钟；
- 默认项目终点和导出终点是主歌曲结束时间；
- 如果只导入歌曲视频，其音轨成为主歌曲音轨；
- 歌词、视频片段和预览播放都从属于主歌曲绝对时间；
- 内部时间使用整数 tick 或微秒，不能使用浮点秒作为持久化格式；
- UI 可按帧或毫秒展示，但数据不绑定特定导出帧率。
- 歌词获取／预览表格的开始／结束秒四舍五入到一位小数；显示取整不参与保存或打轴计算。

### 4.3 素材导入

正式支持：

- 音频：MP3、WAV；
- 视频：MP4；
- 歌词：TXT、LRC、SRT。

导入过程需要：复制文件、读取媒体信息、计算文件指纹、生成波形/缩略图缓存，并在必要时生成低分辨率代理视频。FLAC 和其他视频容器可以在底层支持时导入，但不作为 MVP 验收条件。

媒体工具的标准输出和错误输出固定按 UTF-8 解码，不依赖 Windows 系统／控制台代码页。中文、日文等文件名和内嵌标签不得导致媒体信息 JSON 解析失败；修复不重写原文件、标签或歌曲内容（0.4.5.2）。

### 4.4 歌词文档与编辑器

歌词编辑器支持：

- 新建、粘贴、导入和编辑歌词；
- 新增、删除、排序、合并和拆分歌词行；
- 编辑主文本、读音、罗马音和翻译辅助行；
- 合并、拆分、排序演唱单元；
- 建立显示范围与演唱单元的多对多映射；
- 标点默认不生成时间单元；
- 标记间奏、跳过、稍后处理和仅显示不扫色；
- 编辑操作进入统一撤销/重做历史。

双行内容类型必须显式区分：

- 原文 + 拼音；
- 原文 + 假名；
- 原文 + 罗马音；
- 原文 + 翻译。

主歌词拥有演唱时间；辅助行在 MVP 中跟随主歌词显示，不独立打轴。

### 4.4.1 联网搜索扩展（0.3.0）

“歌词获取 / 预览”页提供搜索窗口：所有语言通过 `ILyricSearchService` 的 LRCLIB 适配器检索候选版本并预览；已授权文本可由用户粘贴并记录来源。0.3.12 起不再提供 UtaTen 浏览器搜索入口。

只在点击搜索后发送歌名/歌手，不上传素材；不调用 AI、无 API Key。候选结果显示歌手、专辑、时长及是否包含行时间，用户确认后导入 TXT/LRC，替换现有歌词时再确认，进入撤销历史。保留原始歌词文件、来源 JSON 及项目中的 `LyricSource`。LRC 行时间不保证准确，也不作为 AI 对齐结果。

后台搜索可取消，超时 20 秒，顺序请求与 300 ms 间隔，短期内存缓存，尊重服务限流 Retry-After；响应和文本大小有上限。没有结果、断网或接口变化时可粘贴已授权文本或从本地文件导入，不自动重试、补写歌词或绕过网站限制。

AI 不用于当前检索；后续如需含糊歌名匹配、整理或翻译，按用户偏好优先评估 DeepSeek，但须单独明确数据发送和费用。本版不加入未实现的 AI 开关。

### 4.5 日文自动注音（原功能）

- 对歌词中的所有日文汉字生成假名读音；
- 假名保存到独立读音层，不改写主歌词；
- 从确认后的假名生成罗马音；
- 打轴前必须完成汉字假名读音，未识别的读音不得用于录制；罗马音仅为可选的小字参考，缺少罗马音不阻止按正确假名录制；
- 按演唱音节分组：拗音/小元音与前面的假名组合，促音 `っ`、拨音 `ん` 及长音符 `ー` 并入前一单元；普通大字元音保留单独单元，如 `じょ｜う`；
- 词典分词边界不能打断上述组合；`ヶ/ヵ` 根据校正后的读音拆分，不能因字形小而并入前字；
- 用户可以修改读音并合并或拆分演唱单元；
- 人名、地名、当て字和特殊唱法允许人工覆盖；
- 已确认或手工修改的读音不得被重新分析静默覆盖。

读音状态：

```text
generated  自动生成，待确认
confirmed  用户确认
manual     用户手工输入或修改
```

自动注音处理所有含汉字的词段，结果均可编辑，不承诺自动结果始终正确。首版内置 MeCab/IPADIC 离线词典；词典未收录的生僻字、专名和特殊唱法会保留原文作为待校对占位，必须人工填写假名，不把占位视为正确注音。

0.3.3 分组示例：`一緒 → いっ｜しょ`；`戦場ヶ原 → せんじょうがはら → せん｜じょ｜う｜が｜は｜ら`；`ちゃん`、`ディ` 各为一个单元。0.3.4 修正：录制始终以假名为准，假名在上、原文在下，共享汉字只显示一次，罗马音为默认隐藏的小字参考。手改整句假名同步重建打轴单元，汉字词组保持可编辑的显示映射。旧项目保留现有时间，可选中行“按语言重新分组”采用新规则；已打轴的行重新分组前提示并提供撤销。

### 4.7 手动打轴工作台

0.3.1 修正：卡拉 OK 逐字/日语音拍是默认和主要工作流；无需先逐行打轴。一空格对应一个演唱单元，按提示条依次记录，自动跨句，可用 Enter 在完整句末记录尾字结束并应用，也可整曲录完后额外一空格记录结束点。退格/重做按单元跨句推进。未完成句不能用均分补齐冒充精确时间，未录后续句保持原数据。

支持两种精度：

1. 逐单元打轴（默认）：按中文字、英文单词或日语演唱音节记录入口和尾字结束，连续跨句；
2. 逐行打轴（辅助）：记录每行入口，仅用于快速草稿，不作为逐字录制的前置要求。

录制界面至少显示当前行、上一行、后续一至两行、当前等待单元、音频波形、播放头、已记录时间点、歌曲进度和醒目的录制状态。

0.3.4 录制显示规则覆盖上述多行建议：只显示当前句与下一句两行，长句保持同行横向滚动并跟随待录单元，跨句时整体推进，退格时可以回到上一句。点击单元后可在它前面换行，或把该句与下一句合并，保留读音映射、单元时间及未应用打点；操作暂停播放，可继续录制或撤销/重做。

默认快捷键：

| 按键 | 行为 |
|---|---|
| 空格 | 记录下一歌词单元 |
| 退格 | 撤销最近一次记录，播放不中断 |
| Esc | 暂停或退出录制状态 |
| Enter | 完成当前行/区间 |
| 左/右 | 小幅回退/前进 |

必须支持：

- 无中断撤销与重做；
- 只重录选中行或区间；
- 从目标前 2–5 秒倒数进入；
- 0.5×、0.75×、1×播放，尽量保持音高；
- 区间循环；
- 全局输入延迟补偿；
- 拖动、方向键微调、批量移动和整行偏移；
- 跳过、稍后处理和回退上一行。

### 4.7.1 项目节拍器（0.4.2.0）

- 单组项目级配置，默认关闭，BPM 120，首拍偏移 0 ms；BPM 支持 20–400 小数，偏移为 ±600000 ms 内整数。
- 预览页可开启／关闭并应用 BPM／偏移／吸附细分（每拍 1／2／3／4／6／8 格）；正偏移延后第一拍，负偏移将第一拍置于歌曲开始之前。只使用歌曲区间内的有效网格点。
- 节拍声在歌曲试听输出链路合成，共享设备时钟；暂停、跳转、循环及保音高变速跟随歌曲，不使用 UI 定时器发声。
- 开启时，打点先输入延迟补偿再吸附最近拍点；正中间取后一拍。原始按键时间保留，同拍重复点或范围内无有效拍点明确拒绝，不产生零长度单元。
- 歌曲最后不足一拍时，终止点允许使用歌曲真实终点（Enter 或完整录制后的额外空格），演唱入口仍遵循拍点规则。
- 仅影响新打点；已有待应用／可重做打点也允许修改配置及撤销／重做节拍设置，旧点保持原时间，重做旧点不重新吸附。
- 设置保存入项目及恢复文件，支持撤销／重做；节拍声按整拍用于试听，不随吸附细分加快，不写入导出媒体。多个 timing point／拍号留作后续扩展。

### 4.8 视频时间轴

2026-10-16 按歌词制作工具定位简化：固定一条歌曲／声音轨、一条可含原声的视频轨、一条字幕轨；视频片段不能重叠。取代 2026-10-13 的多轨方案，未公开发布阶段不提供旧多轨转换。

- 移动、复制、删除视频片段；
- 左右拖动、片段吸附、播放头处分割；
- “顺序拼接”按原开始时间紧密排列视频片段，支持撤销；
- 裁切片段头尾；
- 顺序拼接多个片段；
- 片段允许重排和存在间隙；
- 每个片段提供独立静音开关；
- 视频原声在裁切、移动时与画面保持绑定；
- 背景视频默认静音，作为歌曲视频导入的主素材默认不静音；
- 主歌曲与启用的视频片段原声可以同时播放。
- 主歌曲轨独立；视频原声包含在视频轨，不额外展开音轨，裁切／移动保持一致；不提供多歌曲剪辑。

首版不提供独立音量曲线、淡入淡出或效果器。若视频轨在歌曲范围内没有片段，该区间预览和导出为纯黑画面，歌曲与字幕继续播放。视频超出歌曲终点的内容默认不导出。

空白区间必须作为明确的时间范围存在，以便后续 AI 生成的视频作为普通片段填入。MVP 不显示不可用的 AI 入口。

### 4.9 字幕布局与渲染

从 0.4.6.0 起取消下方 30% 的固定限制。仍同时显示两句、左上和右下交替成为当前行，整体从画面底部随字号向上扩展。字号不再受 30% 区域压缩；仅在文本超宽或两行超过整个画面可用高度时等比缩小。横屏、竖屏、方形和 4:3 使用相同规则。旧工程的 SafeAreaRatio 字段为兼容读写保留，不再参与渲染；工程 schema 仍为 9。

- 字幕区域默认透明，不遮盖视频；
- 当前行按单元连续扫色，下一行保持未激活颜色；
- 当前行结束后，下一行激活，空出的位置载入后续歌词；
- 支持字体、字号、未激活色、激活色、描边、阴影、行距和区域边距；
- 用户不能自由拖动行位置；
- 主歌词与辅助行需要独立字号，但作为一个布局单元移动；
- 预览和导出必须调用同一个排版及字幕绘制核心。

字幕选色（0.4.6.1）：四个文字／描边颜色项显示色块、可编辑色号及复制按钮。点击色块打开二维饱和度／亮度调色盘，配合色相、不透明度滑块和常用颜色；支持键盘微调、还原和取消，取消不改原参数。可复制粘贴 `#RRGGBB`／`#AARRGGBB`（可省略 `#`），AA 为透明度；写入时规范化，棋盘底纹用于预览透明色。无效输入明确提示且不能应用，已唱描边留空仍表示沿用未唱描边。预设调用、全局样式保存及工程读写保持一致，schema 不变。

常用字幕样式与全局偏好（0.4.6.0）：

- 字幕样式页可以命名保存完整参数、调用、确认覆盖同名样式及删除；内置配色样式仍保留。
- 保存常用样式不直接改写工程；调用先填入编辑参数，沿用样式页现有的应用、工程保存及自动恢复点收集流程。点击“应用字幕样式”可立即预览。工程保留样式值，不依赖全局预设 ID，删除或覆盖预设不影响已应用的工程。
- 全局配置 `user-preferences.json` 位于 EXE 同目录，首次保存常用样式时创建，可随便携软件搬迁。跨工程共享，与 `.lrn` 及工作区恢复文件分离。
- 配置 schema 为 1，保存 `subtitleStyles` 和 `roles`（0.4.7.0 新增，旧配置默认为空）；保留 `apiConnections` 的 endpoint/model/credentialReference 元数据。2026-10-28 开发版新增 `aiProviders` 和当前 Windows 用户加密的凭据负载，详见产品定义中的 AI 界面与连接配置规则；不保存明文 APIKey / AK / SK。
- 写入采用独占锁、临时文件和原子替换，上次成功配置留作 `.bak`。无法写入程序目录时显示权限提示，不静默改到其他目录；损坏或不支持的配置不自动清空覆盖，内置样式继续可用。更新软件时用户需保留自己的配置文件，不随发行包分发个人配置。

### 4.10 预览与导出

预览：

- 目标刷新率为 24 fps；
- 音频为主时钟，视频帧、播放头和字幕追随音频时间；
- 性能不足时降低视频预览分辨率或使用代理，不改变最终导出；
- 允许偶发预览掉帧，但不能让音频或时间轴时钟累计漂移；
- 空视频区间显示黑色。

导出：

- MP4 容器、H.264 视频；
- 16:9、4:3、1:1、9:16；独立选择 720p／1080p，按短边映射，最大为 1920×1080 或 1080×1920；
- 24、30、60 fps；
- 包含背景画面、主歌曲、启用的视频原声和字幕；
- 离线渲染，不要求实时速度；
- 导出进度可取消，取消后清理不完整输出；
- 相同时间点的字幕排版与预览一致。

## 5. 非功能需求

### 5.1 兼容性目标

“十年内电脑可使用”定义为硬件兼容目标，而不是承诺支持已经停止维护的 Windows 版本。

MVP 正式支持：

- Windows 11 x64；
- 仍处于厂商支持期的 Windows 10 Enterprise/LTSC x64，可作为兼容测试目标；
- 8 GB 内存最低、16 GB 推荐；
- 支持 DirectX 11 的显卡；
- 无独立显卡也可运行，但允许降低预览质量和延长导出时间。

首版只发布 x64。ARM64 和 x86 不作为 MVP 发布目标。

### 5.2 性能与可靠性

- 1080p 项目在推荐配置上以 24 fps 为预览目标；
- 长时间播放时音画累计漂移应可检测并纠正；
- 时间轴交互不能因波形或缩略图生成而阻塞 UI；
- 所有缓存、分析和导出任务在后台执行并支持取消；
- 项目保存、素材复制和导出必须报告明确错误；
- 时间编辑、歌词编辑和片段编辑使用统一可撤销命令系统。

### 5.3 可测试性

- 数据模型、歌词拆分、时间约束和项目迁移可无 UI 单元测试；
- 字幕渲染支持固定时间点的图像快照测试；
- 导出后用探测工具验证分辨率、帧率、时长和流信息；
- 使用至少一台低配设备做端到端性能测试；
- 日文测试集必须包含组合假名、促音、长音、熟字训、人名和当て字。

## 6. C# 技术栈评估

### 6.1 结论

C# 适合此项目。推荐使用 **.NET 10 LTS + WPF** 构建客户端，把媒体解码、同步、字幕绘制和导出放在独立模块中，不让核心业务依赖 WPF 控件。

.NET 10 是当前 LTS，支持至 2028 年 11 月。WPF 是成熟的 Windows 专用 .NET UI 框架，具备 XAML、数据绑定、样式、模板、2D 图形和硬件加速等能力。虽然微软将 WinUI 3 作为新 Windows 应用的通用推荐，但本项目包含高密度时间轴、键盘工作流、大量自绘和原生媒体互操作；WPF 的成熟度、工具生态和部署可控性对 MVP 更有价值。

### 6.2 方案比较

| 方案 | 优点 | 主要代价 | 结论 |
|---|---|---|---|
| .NET 10 + WPF | 成熟、资料多、数据绑定和自定义控件稳定、原生互操作成熟 | 默认外观较传统；复杂画布仍需自绘 | 推荐 |
| .NET 10 + WinUI 3 | 现代 Fluent 外观，微软对新通用 Windows 应用的主要推荐 | Windows App SDK 部署和版本层更复杂；高密度编辑器仍需大量自绘 | 可选但不作为 MVP 首选 |
| C# + Avalonia | 跨平台、XAML 风格 | 当前明确只做 Windows；多媒体互操作和发布测试面扩大 | 暂不采用 |

### 6.3 推荐依赖

- UI：WPF on .NET 10；
- 架构：Domain / Application / Infrastructure / WPF App 分层，界面使用可绑定编辑行和局部窗口控制器；MVP 未引入额外 MVVM/DI 框架；
- 日志：工作区 `logs/application.log`，错误同时在界面呈现；
- 项目序列化：`System.Text.Json`；
- 2D 字幕和时间轴绘制：WPF 绘图核心（具体实现见 7.2）；
- 音频输出与主时钟：`NAudio.Wasapi`；
- 媒体探测、代理、波形提取和最终编码：固定版本的 `ffprobe`/`ffmpeg` 子进程；
- 测试：xUnit；
- 日文读音：`IJapaneseReadingService` + `LibNMeCab.IpaDicBin 0.10.0`，词典随包部署，无需日语语音包；
- 媒体工具：Gyan FFmpeg 8.1.2 essentials，版本和 SHA256 固定在 `scripts/media-toolchain.json`。

第三方依赖版本必须由集中包管理锁定。FFmpeg 大部分代码使用 LGPL，但启用部分可选组件后整体会受 GPL 约束；发布前必须固定构建来源、配置和许可证清单，不能随意从网络下载未知构建。

## 7. 推荐运行架构

```text
WPF Shell / Views
        ↓
Application（用例、命令、撤销、任务调度）
        ↓
Domain（项目、歌词、时间轴、样式；无 UI/媒体依赖）
   ↙          ↓             ↘
Workspace   Playback       Rendering
   ↓          ↓             ↓
文件系统   NAudio + 视频   WPF 共用字幕核心
              ↓             ↓
           主音频时钟  ← 统一时间采样
                    ↓
             FFmpeg Export Pipeline
```

关键原则：

- 主音频时钟是播放状态的唯一真相；
- 视频在预览时静音显示，其音轨预先解码/缓存后由音频混音层播放，从而避免两个播放器各自走时钟；
- 视频层根据主时钟选择当前片段并纠正 seek 漂移；
- 字幕渲染器输入“时间 + 布局尺寸 + 歌词数据 + 样式”，输出画面，不读取 UI 状态；
- 预览与导出共用字幕布局和绘制代码；
- FFmpeg 只通过接口暴露，不让命令行字符串散落在业务层；
- 日文分析器可替换，用户确认的数据与具体词典实现无关。

### 7.1 播放技术风险

WPF 自带媒体能力底层依赖 Windows Media Foundation，适合先验证 MP4 视频显示；音频由 WASAPI 播放并充当主时钟。微软没有为 Media Foundation 提供官方托管 API，因此不能在未验证的情况下承诺它足以承担最终精确播放器。

首个 PoC 必须验证：

1. 连续播放 10 分钟的音画漂移；
2. seek、循环和 0.5×/0.75×/1×变速；
3. 片段切换与黑场间隙；
4. 视频原声抽取后与主歌曲混音；
5. 低配设备上的 1080p/24 fps；
6. 中文、日文字幕的预览与离线帧像素一致性。

若 WPF/Media Foundation 视频层无法满足同步要求，只替换 `IVideoPreviewBackend` 为 FFmpeg/Direct3D 实现，不改动领域模型和编辑器。

### 7.2 当前字幕绘制实现（2026-10-12）

字幕 MVP 当前采用 WPF 的 `FormattedText`、字形几何和离线 `RenderTargetBitmap`，尚未引入 SkiaSharp。此选择沿用现有桌面框架的中日文字体回退和排版能力，减少当前依赖；后续可以通过字幕帧接口替换具体绘制器。

- `Application.Rendering.SubtitleSceneBuilder`：纯数据计算两句的显示位置、演唱单元进度、共享汉字词组映射和辅助行进度；不依赖 WPF。
- `Infrastructure.Rendering.WpfSubtitlePainter`：主歌词及辅助行排版、描边、阴影、按显示范围连续填色；预览与离线输出共用。
- `App.Controls.SubtitleOverlay`：在当前项目输出宽高的逻辑画布上调用共同绘制器，预览画布等比缩放，横竖屏均与导出一致。
- `Infrastructure.Rendering.WpfSubtitleFrameRenderer`：独立 STA 渲染线程，通过同一绘制器生成最大 1080p 的字幕帧，并转换为直通 Alpha 的 BGRA 像素。

字幕按字号从底部向上扩展，左上与右下两个位置轮流成为当前句，不再限制在下方 30%。辅助行置于主歌词上方；可选择不显示、假名、拼音、罗马音或翻译。仅当超出画面宽度或双行可用高度时整体缩小，不增加自由拖动布局。

0.3.4 日语显示规则：默认只在汉字词组上方标小字假名；项目级 `ShowRomanization` 默认 false，开启时改为在对应汉字/假名原文上方标罗马音，不叠加假名注音。按单元的显示范围合并共享词组，为注音预留宽度防止挤叠，注音高亮跟随对应原文范围。打轴与样式页开关同步，保存/重开后恢复，预览及导出一致。中英文保留既有辅助行规则。

自动检查已覆盖共享汉字词组的多音拍扫色、辅助行进度、精确时间边界的交替、间隙与间奏、禁用扫色、透明帧、字幕区域边界、小字号注音可见性和跳转后的帧一致性。研发 PNG 快照仅用于测试，未作为对外字幕素材导出功能提供。完整 MP4 合成已实现并经过真实编码/探测测试，低配设备性能仍待统一人工验收。

### 9.3 Agent 基础业务工具（2026-10-31）

## 11. MVP 实现决策与统一验收

本版采用以下固定实现：

1. 中文拼音手工编辑；日文通过内置词典生成初始假名和罗马音，用户校对；
2. 辅助行在主歌词上方，字幕随字号从底部向上扩展、无 30% 限制，双句左上/右下交替；
3. 视频原声仅提供静音开关，与主歌曲混合并限幅；
4. 视频轨支持静态图片和视频，无片段时为黑底；可选频谱与字幕叠加在背景上，不提供 AI 背景入口；
5. H.264 使用项目预设码率编码，不开放高级编码器参数；
6. 20 秒自动保存到独立 `project.recovery.kfp`，不覆盖最后一次显式保存的 `.lrn` 项目入口（旧单轨项目仍可使用 `project.kfp`）；
7. 发布为 Windows x64 自包含便携 ZIP；这是软件发布包，不是后续版本的工作区打包功能；
8. 实际程序集为 App、Application、Domain、Infrastructure，按第 8 节职责分命名空间；测试对应四个程序集。

- DeepSeek 校正请求显式 thinking.type=disabled，不发送 reasoning_effort，max_tokens=8192。第一步单JSON对象，第二步NDJSON。空白/仅思考的正常终止单独报错，finish_reason=stop 后立即退出读取。0.5.1.3 曾在连续两批无结果后停止；0.5.1.4 起按下方失败隔离规则继续处理后续分区。
- 原始假名允许错音；建议读音不再要求与引用观察完全相等。未找到观察、多解、特殊唱法仍提示复核；所有AI结果仍不是人工确认。
- 官方依据：https://api-docs.deepseek.com/guides/thinking_mode/ 与 https://api-docs.deepseek.com/guides/json_mode/ 。

### 读音校正失败隔离与括号（2026-11-05）
- 取消“连续两批失败停止”：可恢复的格式、字段、网络读取及超时错误标记当前分区，继续下一分区；身份/权限/限流等不可恢复配置错误以及用户取消仍终止请求。
- 一个已解析的句子映射无效不影响同批其他句子；界面列出失败行号与阶段，行标题和确认窗口展示具体原因。诊断记录安全的异常类型，不记录原始异常正文或密钥。
- Omni 允许汉字与假名混合，作为可能错音的听写线索；DeepSeek结合原词进行近音推断，所有结果仍需人工确认。
- 括号符号不进入打轴发音。明确的重复注音通过 notSung 的完整括号片段表达，不重复打点、不删除原歌词；实际唱出的括号内容保持可打点。判断不明继续待确认。

### 读音直接应用与映射自修复（0.5.1.5）
- 本节取代此前 AI 待确认及两阶段读音严格相等规则。成功读音直接应用，来源仍为 Generated，不冒充人工确认；不再生成待确认队列、橙色疑点下划线或逐句确认按钮。旧 review 记录按已应用展示，实际失败仍显示原因和错误标记。
- 中间整句读音是推断参考，最终分段允许进一步纠错（包括当て字及括号重复音），不与旧读音或中间读音强制比较。仍保留目标行绑定、原文完整覆盖、有效假名和数据大小校验，避免把丢字或破损数据写入工程。
- 忽略模型冗余的原文回显，使用请求时的原文；可选的 null 说明/证据规范为空。分段覆盖或假名字段无效时，自动向文本模型提交原文、观察、失败分段及具体结构错误，单句修复一次。修复失败保留旧内容并继续后续分区；无无限重试。认证/限流及用户取消仍停止。
- 校验诊断记录具体分类（surface-coverage、annotation-shape、missing-kana、invalid-fields、stale-source）；不记录密钥、供应商原始错误正文。校正可撤销并自动保存，人工内容与已打轴单元仍保留。

### 注音括号清理（0.5.1.6）
- 覆盖此前“不删除已判定注音原文”的规则：AI 明确标为 notSung 的注音括号，在应用时连同括号和内部文字从歌词正文删除，再重建读音、显示范围与字幕布局；原文保留在校正详情，操作仍可撤销。
- 接受完整括号、括号拆成多个片段，以及汉字与注音合并在同一个片段的常见输出。归一化明确标注的注音，将其读音用于对应汉字（如夢幻/ゆめまぼろし），不再因重复 reading 字段拒绝。
- 只有明确标为注音的块才清理；实际唱出的和声、独白和重复唱词保留。人工确认与已打点内容仍保护。

### 全文后恢复（0.5.1.7）
- 文本校正/映射首轮遇到响应中断或可恢复错误，保留成功句，暂存失败原因后继续全文。首轮结束后先用本轮原文完全相同、且无不同读音冲突的成功结果补齐失败句；复制的是读音映射，重新绑定目标行，不复制时间点/单元ID。
- 无可复用结果的失败句逐句重试，首轮之外每句最多两次；取消原先即时映射修复，避免叠加重试突破上限。结构错误也使用同一恢复队列。成功的整句读音缓存于本轮，映射失败仅重试映射，不重跑 Omni 或已完成的整句读音请求。
- 重试中新增成功结果可供后续失败句及已耗尽重试的重复句复用。认证/权限/限流等不可恢复错误和用户取消立即停止。最终每句只提交一次成功或失败，保存/撤销及人工内容保护仍有效。
- 进度与诊断显示 duplicate-reuse、line-retry 行号及第1/2次，未恢复的结果明确标识已重试两次。缓存仅用于本轮，不跨项目使用。

### 重复歌词注音一致性（0.5.1.8）
- 映射请求补充全文 context。针对格式合法却把注音唱两遍的结果：当全文存在删除该括号块后完全相同的歌词，且括号为假名并等于紧邻前方连续汉字片段的合并读音时，归一为注音并清理。支持逆/さか、夢/ゆめ等拆分映射。无对应歌词或读音不符时不据此删除，保留原有唱词与显式注音处理。

### 0.5.2.1 歌词编辑与打轴补救
- AI 可导入 TXT/LRC 文本，按行 ID 与原文校验替换、插入、删除、移动歌词，或指定日语原文片段修正读音。先准备候选结果并展示审批，批准后保存整个项目并支持撤销；内容变化拒绝执行。
- 自动时间点的句内空隙延长至下一单元开始，末单元保留实际终点。已有人工单元不覆盖；部分人工打轴句仍可补其他单元。
- 人声对齐优先保留有效且不冲突的锚点，缺失/冲突单元在相邻锚点之间线性分配；无可靠锚点不生成整句等分时间。日志记录插值单元。重叠区间取并集，以最终句长为分母，超过 5% 时仍应用并显示“AI识别失败，推荐人工审核”。
- 自动对齐终点以 AutoAlignmentEnd 独立保存，不冒充人工 Enter。相邻两句允许重叠，但入口仍依序，禁止跨句/三句重叠。仅已完成且有效的行参与冲突检查，未完成的其他行不阻塞本句。
- 全文首轮完成后，对有可靠前后邻句的失败/重叠句，在前句结尾至后句入口的非重叠空档重试一次。重试不成功不证明真实演唱重叠；无可用空档保留原结果或失败原因。失败与取消不会改动人工点。
