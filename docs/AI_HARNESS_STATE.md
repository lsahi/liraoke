# AI 会话、长期记忆与长任务

## 生命周期

Pi/Cordis 聊天没有客户端自动超时：不对整轮、模型等待、审批等待或工具执行设置期限。HTTP 连接、响应头和响应体的客户端时限也关闭。用户点击聊天“停止”、取消当前任务或关闭 App 才主动取消相应工作。服务商和代理仍可能主动断开，遇到这种错误保留上下文并如实显示失败。

关闭窗口先取消聊天与工具，等待会话检查点落盘，再继续既有项目保存提示和退出流程。收起聊天框只隐藏界面，不取消聊天。安装等任务随 App 关闭而取消，不承诺关闭后在后台继续，也不自动重放未知结果的操作。再次对话时先查询插件/项目状态，再决定是否重试；安装必须通过自检才算成功。

这里取消的是聊天 Harness 的通用期限。具体业务服务的请求预算、重试次数和安全校验仍由各服务负责，不能将聊天长期等待理解成业务请求永不失败。

## 会话恢复

默认保存位置为 `%LOCALAPPDATA%/KaraokeFilmMaker/ai-state`，与安装目录、工作区分离。会话按 AI 配置 ID 隔离；新项目仍可沿用用户会话，但每轮必须重新读取当前项目状态。更换配置在当前轮结束后生效，防止旧任务写入新会话。

- 发送前保存用户消息；工具请求与工具返回结果分别即时保存。
- 回复生成时约每 5 秒保存一次部分正文，结束、停止或失败时保存最终检查点。
- 不持久化服务商思考文本；已配置凭据和可识别的密钥内容由凭据检查过滤。
- 文件使用 Windows 当前用户 DPAPI 加密，临时文件写完后替换；损坏文件保留，不静默覆盖。
- 上次未结束的记录带状态未知提示；请求记录不等于成功。重启后不自动执行历史写入操作。
- “新对话”归档旧文件，保留用户长期记忆。当前界面显示最近 60 条；旧文件没有历史浏览器。

全量记录与发给模型的上下文分开：模型只接收有界的近期记录（最多 80 条，约 9 万字符），超长工具结果裁短并提示重新读取；补充有限的早期用户请求摘录。这是保守裁剪，不是 LLM 摘要，也不保证无限上下文。全量文件达到约 30 MiB 时提示另开新对话。已有旧版的内存会话无法追溯恢复。

## 用户长期记忆

聊天区“记忆”可查看、编辑、删除偏好；新聊天和新工作区都保留。最多 100 条、合计 8000 字。Agent 通过 `get_user_memory` 读取，通过 `remember_user_preference` / `forget_user_preference` 请求变更；写入或遗忘需用户 Approve。仅在用户明确要求时记录偏好，不自动把对话推断、临时任务或项目状态当成长期事实。长期记忆会提供给当前所选服务商，不能作为工具授权。

## AI 执行期间的交互

现有资源的写入、删除、歌词/样式编辑、项目切换与撤销锁定；播放、暂停、跳转、速度调整仍可使用。时间轴进入只读选择/定位模式。图片、视频、音频可以继续导入素材库，但不立即替换主音频或加入视频轨道。只有新增资产合并回正在处理的项目；不覆盖 AI 已完成的部分结果。AI 结果应用时允许这种纯新增，拒绝其余并发更改。撤销 AI 变更保留用户期间新增的素材。

收起或重新打开 AI 面板不能绕过写锁。长任务结束、失败或取消后恢复编辑。关闭 App 同时取消进行中的素材导入，避免退出后继续更改项目。

## 进度编码与验证

本地插件进程输入输出按 UTF-8 处理，Python 强制 UTF-8/unbuffered；pip 使用 raw 下载进度并转换成中文 MiB 计数，避免 Windows CP936 终端解码导致乱码。

离线回归覆盖持久化与恢复、用户偏好、新会话、部分回答/工具结果、真实 Node HTTP 往返与取消、关闭窗口、播放/定位与真实图片导入、中文进度解码。测试超时只用于测试进程防挂，不是产品聊天期限。自动测试不替代真实供应商长时间连接和完整大模型下载的人工验收。

同一轮用户消息对同一个插件最多发起一次安装申请，包括不同 CPU/GPU 参数。此限制由每轮创建的工具桥执行，失败、拒绝或成功后都不能再次弹同插件审批卡；其他插件不受影响，用户新发一条明确重试消息后可再次申请。模型下载失败不会自动降级为 CPU 安装。

执行前的空闲检查与执行中结果提交的检查分离：新工具请求仍需客户端空闲；已经持有 AI 任务忙碌状态的打轴任务，提交时验证任务仍有效、项目身份、关闭状态、取消状态和内容一致性，不因自身 `_isBusy` 而拒绝结果。允许期间只新增素材，禁止覆盖其他资源变动。提交后仍逐句验证、保存并支持撤销，失败句报告真实原因与数量。
