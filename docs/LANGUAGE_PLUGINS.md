# 语言包开发说明（API 1）

> 更新日期：2026-10-15  
> 适用项目格式：schema 4（沿用 schema 3 的语言元数据及插件 API）  
> 范围：完整的语言适配器与策略、离线混合语言识别、可保存的显示方案。此接口仍处于早期阶段。

## 1. 一套语言包负责什么

语言包不只是分词器。内置中文、英语、日语和第三方包通过同一份 `ILanguageAdaptor` 契约提供：

- 语言 ID、显示名称、实现版本和所需能力。
- 离线识别证据：这个片段是否适合交给该语言处理。
- 演唱／打轴单元及其原文映射。
- 打轴格的主要文字、辅助文字和可选罗马化转写。
- 字幕原文、注音、转写及它们与演唱单元的映射。
- 开始录制前的检查，例如必须补齐的读音。

插件返回纯数据，不创建 WPF 控件，不接管播放器或导出器。主程序负责混合片段的组合、时间轴、排版、绘制与保存。预览和导出消费同一份显示数据。

识别、分词和注音不在播放计时器或按空格的热路径中执行。已生成结果保存在项目中；安装或升级插件不应自动改写已有结果。

## 2. 安全边界与加载方式

**DLL 插件是可执行代码，不是安全的数据文件。** 用户必须信任作者及下载来源。插件构造函数在加载时就会运行，它可以拥有与客户端进程相同的文件和网络访问权限。

客户端只加载用户明确选择的插件 DLL；不会因为打开项目、看到某个语言 ID，或在工作区发现 DLL 就扫描、下载和执行插件。本次实现不会在下次启动时自动重新加载第三方代码，需要重新选择可信插件。

每次加载使用独立的 `AssemblyLoadContext` 和依赖解析器。这用于减少第三方依赖冲突，**不是安全沙箱**，不能限制恶意插件、强制终止死循环或阻止进程级错误。取消令牌也依赖插件配合。不要把运行不可信插件当作普通的文件导入。

宿主共享 `KaraokeFilmMaker.Application` 和 `KaraokeFilmMaker.Domain` 两个契约程序集，不能让插件私有副本形成另一套类型身份。插件 DLL 及其依赖应保留在同一发布目录中，不要把依赖散放进工作区。升级契约后需要重新编译和验证兼容性。

加载器会拒绝：

- 损坏／非托管 DLL、缺失依赖、无公开入口或无公开无参构造函数。
- 与 `BaseLanguageAdaptor.CurrentApiVersion` 不一致的插件。
- 重复语言 ID，包括试图覆盖内置 `zh`、`en`、`ja`、保留 ID `und`。
- 无效的元数据或宿主尚不支持的能力。

API 1 的宿主显示方案目前只接受从左到右书写（LTR）。不要声称已经支持阿拉伯语等所需的 RTL／复杂双向排版。需要这些能力时，应先扩展宿主的排版、编辑、扫色和导出验证，再更新能力协商。

## 3. 入口与策略

参考源码：

- `src/KaraokeFilmMaker.Application/Languages/LanguageContracts.cs`
- `src/KaraokeFilmMaker.Domain/Lyrics/LanguageModels.cs`
- `examples/language-plugin/SpanishLanguageAdaptor.cs`

入口类必须公开、非抽象、有公开无参构造函数，并实现 `ILanguageAdaptor`。建议继承 `BaseLanguageAdaptor`，处理规则继承 `BaseLanguagePolicy`。一个 DLL 可以提供多个语言入口，但整批验证通过后才注册。

`LanguageId` 使用稳定的语言标识（例如 `es`），不要使用本地化名称或版本号；`Version` 单独记录处理规则版本。`ApiVersion` 是宿主接口版本，不等同于插件自身版本。

### Detect

`LanguageDetectionContext` 提供当前片段、整句、整份歌词和可选默认语言提示。返回 `LanguageEvidence(Score, Reason)`：

- 分数是可比较的规则证据强度，不是统计概率。
- 没有正向证据时返回 0，不要因“使用拉丁字母”就给某种语言高分。
- 使用词典、词尾、功能词和相邻上下文；不能仅凭汉字判断中文，也不能仅凭字母判断英语。
- 分数建议使用 0–100；越高必须有越明确的证据，保留可解释的 `Reason`。
- 保持快速、确定性、无网络副作用；不要在识别中修改输入或保存文件。

主程序协调各插件证据和语言片段，而不是允许某个插件接管整首歌。手工指定并锁定的片段优先于自动判断。未知文字可以保留为 `und`，不能因为缺少插件而硬套已有语言规则。

### ProposeBoundaries

可选的 `ProposeBoundaries(LanguageDetectionContext)` 用于指出同一文字系统内部可能的语言切换位置。基类返回空列表；普通语言包可以不重写。比如日文句子中的明确中文短语，不能仅靠“汉字／假名／拉丁字母”的文字系统切换识别，中文规则可以建议该短语的起止位置。

返回值是相对于 `context.Text` 的 UTF-16 边界索引，必须落在完整字素之间。主程序验证边界，把所有插件建议合并、排序、去重，再分别调用 `Detect` 评估候选片段。**建议边界不等于认领语言，也不等于最终演唱单元的拆分点**。不要逐字切碎整个句子来抬高匹配率，更不要切开组合字符。

该方法只在自动语言分析时执行，不在播放、字幕绘制或打点时执行；显式锁定的语言片段不会因这些建议被自动改写。规则应快速、确定性、无网络副作用，返回越界或不完整字符位置会使本次分析失败并提示插件错误。

### AnalyzeAsync

输入包含片段原文、时间范围以及可选的人工读音。输出 `LanguageAnalysisResult`，包含三种相互映射但不必一一对应的数据：

若支持用户输入片段读音，需在 `LanguageCapabilities` 设置 `SupportsManualReading: true` 并实际处理 `ManualReading`；未声明时宿主禁用该输入，并拒绝传入非空手工读音，不能静默忽略。内置日语支持此能力，中英文目前通过单元精修或原有辅助行修改读音。

| 输出 | 含义 |
|---|---|
| `Units` | 每次打点对应的演唱单元、读音、可选转写、初始时间和原文范围 |
| `RecordingCells` | 通过 `UnitId` 对应演唱单元，声明打轴格主要／辅助文字 |
| `SubtitleRuns` | 声明字幕片段的原文范围、注音、转写及对应的一个或多个单元 ID |

原文范围是**片段内的 UTF-16 索引**，主程序合成混合歌词时转换成整句位置。不要返回整首歌的索引，也不能切开代理对、组合附加符号或其他完整字素。保留原文，不应为了方便分词静默执行会改变索引的 Unicode 规范化。

初始时间必须落在输入范围内、按序且不重叠；新生成的均分时间不是用户确认过的打点，`IsConfirmed` 应为 `false`。每个单元的 ID 要唯一，格子及字幕引用须对应输出单元。注音边界可以不同于打轴边界：例如日文某个打轴单元包含送假名，并不意味着该送假名应显示在前一个汉字的注音上。

不要猜测无法确定的读音；设置 `NeedsReview` 和可理解的 `Diagnostic`。`NeedsReview` 表示录制前需要处理的问题，不应用于普通说明性提示；非阻塞说明只使用 `Diagnostic`。`GetRecordingIssue` 可以声明录制前必须修正的问题。尊重取消令牌，不要使用 UI 线程、静态可变的全局歌词或后台定时器。

`CreatePresentation(LyricLine)` 在用户修改文字／读音后刷新显示，不负责重新分词或改变时间。基类默认生成普通原文显示；需要注音或特殊打轴格的插件必须重写此方法，使编辑后的规则与首次 `AnalyzeAsync` 输出一致。可选的 `RomanizedSubtitleRuns` 描述开启罗马化转写后独立的字幕分组；省略时使用普通分组。

### GetRecordingIssue 与校验缓存

`GetRecordingIssue(LyricLine, LyricLanguageSpan)` 在分析得到单元后、以及显式歌词编辑刷新显示时调用。此时原文和单元范围均为当前语言片段内的局部坐标。返回 `null` 表示没有阻止录制的问题；返回说明文字则把问题缓存到该片段的待确认状态中。调用失败会作为语言包错误报告，而不是继续接受未检查的结果。

0.4.2.1 起，宿主检测阶段的语言不确定性与实际录制错误分开处理：有完整可用单元时，前者只在录制到该句时显示可忽略提醒，不阻止开始打轴；`AnalyzeAsync` 的实际问题或 `GetRecordingIssue` 的非空结果仍阻断。宿主通过 `LyricLanguageSpan.HasBlockingIssue` 可选属性保存这一区别，旧项目兼容读取；既有位置构造参数及插件 API 版本不变，插件作者不需要重新编写检测或分词逻辑。

必须持续成立的读音规则应在这里实现，不能仅在 `AnalyzeAsync` 中返回一次 `NeedsReview`。用户后续可以快捷修改读音，此方法需要基于最新单元重新判断：问题修好即可清除读音方面的阻断，出现新问题则继续阻断。语言识别本身的歧义另外保存在 `DetectionNeedsReview`，不能因为读音正确就自动确认语言。

真正开始录制时，宿主读取已经缓存的检查结果及内置的数据完整性检查，**不调用第三方 Policy**。播放、字幕绘制和每次按空格也不会重新调用它。缺少插件时保留项目中的结果与缓存，不用其他语言替代原有规则。

## 4. 构建与测试示例

仓库提供一个小型西班牙语演示包，仅用于说明完整接口，**不是经过语言学验证的西班牙语实现**。它使用少量词典证据，按 Unicode 单词分组，不实现西班牙语演唱音节、音标或完整读音校对。示例提供非阻塞的能力限制说明，默认允许按词打轴。

在仓库根目录运行：

```powershell
dotnet build examples/language-plugin/Liraoke.ExampleSpanish.csproj -c Release
dotnet test tests/KaraokeFilmMaker.Infrastructure.Tests/KaraokeFilmMaker.Infrastructure.Tests.csproj -c Release --filter "FullyQualifiedName~LanguagePluginLoaderTests|FullyQualifiedName~LanguageProjectPersistenceTests"
```

在客户端语言插件入口选择：

```text
examples/language-plugin/bin/Release/net10.0/Liraoke.ExampleSpanish.dll
```

开发者至少应测试：

1. 本语言普通歌词、专名、空白、标点、数字和未知词。
2. 与其他语言混写；相似文字不能被错误地全部认领。
3. 组合字符、代理对和完整原文范围映射。
4. 人工读音覆盖，以及注音和演唱单元边界不一致的情况。
5. 打轴显示、字幕显示和两种转写开关状态。
6. 保存／重开、缺少插件、插件升级后既有时间和结果不变。
7. 输出错误、取消、依赖缺失和不兼容版本。

## 5. 工作区兼容性

schema 3 在行中保存语言片段及显示快照，在单元中保存开放的语言 ID 字符串。即使没有安装某个语言包，其 ID、规则版本、人工确认信息、时间和可由宿主绘制的快照也能往返保存。

缺少插件时，主程序可以使用已保存的结果；需要重新识别、分词或生成读音的操作才需要对应插件。不能静默把未知语言改成中文、日语或英文，也不能因为显示快照存在就宣称宿主支持所有文字方向和排版。

旧 schema 1／2 项目升级时只添加语言元数据：原整句语言转换为锁定的默认语言片段，不重新生成单元、ID、时间、人工读音或已确认状态。没有显示快照的旧项目继续使用既有显示路径，不因升级而改画已经完成的歌词。当前再次保存使用 schema 4；新增单轨约束和节拍器配置，不改变语言契约。旧版客户端不保证能打开新格式，因此重要项目建议先备份。

如果更换语言或重新分析会改变已有单元结构，应在明确操作中确认影响范围，而不是在打开项目或升级插件时自动执行。
