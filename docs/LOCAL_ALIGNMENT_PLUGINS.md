# 本地自动打轴插件（初版）

## 使用流程

歌词打轴页右侧有“本地自动打轴 / 插件安装”分区。打开“打轴插件…”可查看本机配置、已安装模型及 CPU/GPU 安装按钮。安装需要联网；本地推理无需 API Key。支持同时安装两种模型，每种模型当前启用一个 CPU 或 GPU 环境。

默认按已经准备好的演唱单元判断主要语言：日语单元超过其余语言总数时使用 NextFire，否则使用 Qwen。用户可以在打轴页面手动指定。缺少首选插件时提示安装，不静默替换模型。

“打轴前校正日语读音”默认勾选，继续调用已有 Omni/ASR＋文本校正流程，包括注音括号、当て字、重复歌词恢复和失败重试。已有成功校正或人工确认读音可直接继续；用户也可明确采用人工审核过的当前读音。对齐模型只负责时间，不重新生成读音。

AI 可通过“检查我的电脑能否安装日语打轴插件”“安装适合我的本地打轴插件”“校正读音并自动打轴”等请求调用同一服务。首次使用读取内置 local-alignment skill。安装和写入时间点均通过现有 Approve 机制；不提供任意 URL、命令或密钥参数。

## 分段与应用

1. 使用 Demucs 从项目原歌曲提取人声，再将人声转换为 16 kHz 单声道，保持原歌曲长度与时间基准。
2. 若导入 LRC 的所有唱词行与当前歌词匹配，使用其句段入口；否则先粗定位整曲句段。
3. 按句段实际裁切音频，输入已校正的演唱单元，逐句推理并加回原歌曲时间偏移。
4. 检查单元 ID、数量、时序、正时长、歌曲边界及句间冲突。无法补救的失败句保留旧时间，继续其余句；有可靠锚点时允许对未识别单元线性插值，无锚点不对整句等分。
5. 应用成功句、记录撤销并自动保存。人工打点和原始录入时间受到保护。

新增可选字段 LyricUnit.IsAutoTimed 区分自动初稿与人工确认，旧工程缺省为 false。自动结果计入已应用单元，仍可人工调整；重新打轴和重建相关单元会清除这个标记。校正读音和打轴是各自可撤销的操作。

初版保守限制：裁切句段不得超过 35 秒；Qwen 在没有匹配 LRC 时只对不超过 5 分钟的整曲做粗定位。NextFire 偏重日语，混合英文需要试听；Qwen 仍可能返回零时长等无效结果。自动生成的句子不伪造 Enter 结尾点，自动终点独立记录，允许相邻两句重叠；三句重叠与逆序仍拒绝，人工 Enter 规则保留。粗定位仍可能包含间奏，最终句内对齐使用裁切音频。

## 插件接口与隔离

Application 定义插件目录、统一输入结果结构、选择和应用校验。Infrastructure 管理硬件检查、安装、独立 Python 进程及日志；App 与 Pi/Cordis 工具共同使用该服务。Python worker 按 backend 适配模型，不把模型 SDK 引入 WPF 进程。

协议 v1：请求包含音频路径、可选 LRC、行 ID、原文、protected、单元 ID/读音/语言；结果为 lines，每行包含同一 ID 和 units(id/start/end)，或 error。时间单位为原曲秒。标准输出使用单行 JSON message 报进度，标准错误用于诊断。取消会终止子进程树。

新增模型需添加目录项、固定版本与文件哈希清单、安装依赖、worker adapter，并通过同一校验和真实推理自检。本版为两个受控插件的兼容接口，尚不是执行任意第三方插件包的通用市场。

安装目录为 %LOCALAPPDATA%/KaraokeFilmMaker/Components/Alignment。每次安装在新目录进行；完成校验和自检后原子切换 active 指针，失败不覆盖旧插件。已校验下载按 SHA-256 缓存，切换 CPU/GPU 可复用；不信任未校验缓存。核心依赖版本固定，传递依赖由官方包索引解析。上游 model card、源代码许可及 wheel 内许可保留。

配置门槛：Windows x64 10 1809 或更新；NextFire/Qwen 分别至少 8/12 GiB 总内存；CPU 安装预留 10 GiB 磁盘。GPU 另需支持当前 CUDA 运行时的 NVIDIA 驱动/架构，分别至少 4/8 GiB 显存，安装预留 20 GiB。门槛是保守筛选，无法保证任意歌曲都不超出内存，最终以自检及任务结果为准。不安装显卡驱动；不支持的 GPU 按钮禁用，CPU 可用时仍提供 CPU 安装。

安装日志在对应插件目录的 install.log；任务日志、请求与结果在 jobs/<时间-ID>/。临时解码音频在任务结束后删除。日志包含歌词和时间点，不包含 AI 凭据。失败安装目录、旧版本及缓存暂保留供诊断；本版未提供自动清理。

## 验证边界

已有 GPU 环境中，两种模型均通过真实加载与推理自检。Hollowood 34 句完成 NextFire 分段推理，其中 10 句因相邻句重叠被应用层拦下，24 句通过应用校验。已用自动时间点实际导出 MP4 并检查字幕高亮。Qwen 日语片段返回有效时间，而英文片段出现无效时长并被正确跳过。此为工程流程验证，不代表人工准确率验收。两种模型都已完成全新 CPU 安装及真实推理自检；依赖从官方源安装，模型使用同版本已校验缓存。两个插件均通过实际应用服务的解码、LRC 定位、裁切、推理、应用校验和临时音频清理流程。

回归：982 项 .NET 测试、15 项 AI host 测试、4 项安装器缓存/校验/安全解压测试通过。安装批准拒绝测试确认不会产生安装目录；人工点保护、自动时间序列化与清空、局部重跑冲突、窄窗口布局均有覆盖。测试命令：dotnet test KaraokeFilmMaker.slnx -c Release；在 src/Liraoke.AiHost 中运行 node --test test/*.test.mjs；使用 Python 3.12 运行 scripts/test_alignment_installer.py。

## 分块下载与本地缓存

大于等于 32 MiB 的固定清单文件采用 16 MiB 分块、最多 8 路并发下载，适用于 CPU/GPU PyTorch wheel 和模型权重。通过单字节 Range 探测确认服务器支持；每个响应严格校验 Content-Range 和大小。服务器忽略 Range 时回退单连接，不能把整文件误拼成分块。网络单次请求有停滞超时和有界重试；聊天 Harness 不因此增加整轮截止时间。

完整分块和校验收据存放于 `cache/downloads/<SHA256>.parts-v1`，独立于每次安装目录。取消、关闭应用或再次安装后，逐块检查本地哈希再续传；未完成分块重新获取，不承诺按单字节续传。合并后必须通过清单的整文件 SHA-256 和大小校验，才进入可复用缓存并交给 pip/模型安装。校验失败不会替换既有可用插件。完成的分块文件清理，合并缓存保留。

PyTorch 2.10.0 的 Windows x64 / CPython 3.12 CPU 与 cu128 wheel URL、字节数和 SHA-256 均固定于 manifest，下载来源与官方索引一致。安装前也会查找本应用管理的 pip HTTP 缓存中已完成的下载，按大小与 SHA-256 双重确认后复用；不会扫描用户的全局 pip 缓存或外部环境。pip 从本地已校验 wheel 安装并解析其余依赖；其余小型依赖仍走官方 pip 索引和缓存。独立 Python 压缩包也可复用完整校验缓存。

插件管理页“导入本地下载文件…”允许多选已有 wheel、模型权重和其他清单文件。只接收大小与 SHA-256 都匹配当前清单的文件，不执行选中的文件，不扫描整个磁盘，也不直接复用外部虚拟环境。改名不影响识别，版本/内容不匹配会计入拒绝数。导入与安装共用排他锁；另一个版本正在安装时不修改缓存。

进度显示已下载/总 MiB、当前下载平均速率、估计剩余时间及复用块数；合并校验独立显示。并发速度取决于服务器、代理、网络和磁盘，不能保证固定倍数加速。旧版本通过 pip 产生的未完成临时 wheel 不自动转换成新分块；完整本地文件可经界面导入，未来新版下载中断则直接续传。

离线测试命令：`python scripts/test_alignment_installer.py` 和 `python scripts/test_alignment_download_ranges.py`。后者使用本机 HTTP 服务验证真实并发、子进程被终止后跨进程/目录恢复、失败块重试、错误范围、短响应、损坏分块、整文件校验和不支持 Range 的降级。测试目录与用户正在运行的插件完全隔离。

下载失败诊断分别报告文件字节数不足、完整文件 SHA-256 不符、分块响应中断（实际/预期字节数）、范围错误和网络/HTTP 错误。下载尚未进入推理自检时不能归因为显存不足；GPU 与 CPU 使用同一份模型权重。Agent 的同插件安装申请受每轮一次的程序限制，不能在 GPU 下载失败后自动弹 CPU 安装卡。

## 打轴使用分离人声

打轴输入先通过现有 Demucs 服务输出 vocals，再转换为 16 kHz 单声道。LRC 或模型粗定位与逐句裁切均使用这份人声，保留整曲前奏、静音与原歌曲时间基准。NextFire/Qwen 共用此准备流程，已校正读音与人工点保护保持不变。

复用随包 CPU 分离组件；只有已安装且硬件支持的 Demucs GPU 组件才自动启用 GPU（独立于打轴插件的 GPU 环境）。沿用分离服务的 GPU 失败回退 CPU。不会自动下载安装；缺组件或分离失败停止本轮，不悄悄退回原曲。每次打轴重新分离，不复用旧伴奏或人声缓存。

临时人声仅写入当前 job 的独立子目录，转码完成后删除；16 kHz 输入在任务结束/取消/失败后删除。任务日志保留分离引擎、阶段进度和异常，请求标注 audioRole=vocals。人声不进入素材列表、不改变当前播放/导出音轨、不新增工程映射。额外的分离耗时与准确率需要分别评估；不保证比原曲对齐更准确。
